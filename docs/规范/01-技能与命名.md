# 01 技能与命名

本文件合并原 01 技能写法、03 命名、07 Agent 设计三份标准；小节标题与正文按原顺序保留，跨文件指针改指新编号。

本文件规定一个技能内各类文件的分工、格式和调用关系。字段的精确取值写在对应模板里，本文件只定规则。

## 目录分工

| 位置 | 放什么 | 谁读 | 是否拷给使用者 |
|---|---|---|---|
| `SKILL.md` | 入口：何时使用、总流程、输入、停止条件、输出 | 技能被触发时整读 | 否 |
| `workflows/NN-名称.md` | 一个步骤组的动作与停止条件 | 进入该步骤组时读 | 否 |
| `references/名称.md` | 判据、策略或概念，被流程引用 | 流程要求时读 | 否 |
| `assets/名称.md` | 版式，技能运行时产出给使用者填写 | 产出时拷贝 | 是 |
| `agents/名称.md` | 子代理的任务书 | 被调用时读 | 否 |
| `scripts/名称.mjs` | 技能专用的确定性脚本 | 命令行运行 | 否 |

判断标准：回答"下一步做什么"的放流程；回答"做得对不对、取什么值"的放参考；回答"谁来做这一块"的放子代理；回答"产出长什么样"的放版式。

## 参考件的三类

一个参考件只放一类内容，不混用。类型由表格形状决定，字段见 `templates/skill/reference.md`：

| 类型 | 回答 | 编号前缀 | 表格列 |
|---|---|---|---|
| 判据 | 合格的标准是什么 | `J-` | 判据、强度、判定方法、依据 |
| 策略 | 遇到什么情况怎么做 | `S-` | 策略名、适用条件、动作、不适用时、依据 |
| 概念 | 这个词指什么 | `K-` | 概念、定义、依据 |

同一类内容超过一个文件时，按对象拆文件，不按篇幅拆。流程只读当前对象的那一份。

判据必须带阈值与单位。写不出阈值时，把"强度"写成"对照"，并在"判定方法"列写"主观判断，由人核对"。不得用"应该""尽量""合理"。

校验器不检查一个文件是否混用三类，这条靠人核对。

## 入口与流程

- 入口只做调度：列出步骤组、输入和停止条件，不写具体动作。
- 流程的文件名以两位序号开头，序号即执行顺序，从 01 起连续。
- 流程之间不直接跳转。切换由入口调度。
- 同一内容只在一处写正文，其他位置写指针。

## frontmatter

规范键（agentskills 开放标准定义的六键）：

| 键 | 必填 | 取值 |
|---|---|---|
| `name` | 是 | 与技能目录名一致，小写英文、数字与单连字符，不超过 64 字符 |
| `description` | 是 | 只写何时使用，以「当」开头（弃用技能例外，见 `03-版本与发布.md`），不列流程步骤，不超过 1024 字符 |
| `license` | 否 | 许可证名，如 `MIT` |
| `compatibility` | 否 | 运行环境说明，不超过 500 字符 |
| `metadata` | 否 | 映射，键值自定；规范留的扩展口，扩展属性优先放这里 |
| `allowed-tools` | 否 | 允许调用的工具，空格分隔，如 `Bash(git:*) Read`（规范标注 Experimental） |

宿主扩展键（基座登记的受控偏差，见 `00-总则.md` 原则 1；只认规范六键的宿主会判为未知键）：

| 键 | 必填 | 取值 |
|---|---|---|
| `whenToUse` | 否 | 触发条件，写 `description` 未覆盖的场景 |
| `disable-model-invocation` | 否 | 布尔，`true` 时模型不主动调用 |
| `user-invocable` | 否 | 布尔，`false` 时用户不能直接调用 |

- 两表之外不得新增键。校验器的 `KNOWN_KEYS` 与两表一致，多一个键报 `E_UNKNOWN_KEY`。
- 每个值写在一行内，不使用多行块标量。
- 布尔键只接受 `true/false`、`yes/no`、`on/off`、`1/0`。
- `description` 句末可补一句不适用条件（如「不当 X 时不用」），并写入用户会怎么称呼这件事的关键词：扩展名、工具名、症状词。

## 长度与拆分

- `SKILL.md` 正文不超过 500 行。超出时把流程拆到 `workflows/`。
- `SKILL.md` 全文（含 frontmatter）不超过 20000 字符：宿主上下文压缩后只重附技能前 20000 字符，超限内容在余下会话丢失。超限时把偶用内容拆到 `references/`。
- 单个参考件超过 300 行时，文件开头加目录。
- 参考件按对象分文件，流程只读当前对象的那一份。

## 调用关系

- 子代理不调用其他子代理。引用层级只有一层深：入口引用流程，流程引用参考、版式或子代理。
- 流程引用子代理时用相对路径指向其文件，不复制内容。
- 引用技能内脚本一律带解释器写 `node scripts/名称.mjs`，不写裸路径：部分宿主的打包器会剥掉执行位，裸路径以权限错误失败。
- 子代理返回的结果，由调用它的流程检查必需字段。缺字段则不采信。

## 示例与发布

示例技能不放在 `skills/`。框架提供的示例见基座 `examples/skills/`，派生项目时删除。

`templates/` 不是发布内容，但必须随项目保留：`scripts/init-skill.mjs` 运行时读取 `templates/skill/`。删除它会让生成脚本失效。

本文件规定仓库、技能、文件和目录的命名规则。

## 仓库

- 仓库名 kebab-case，小写英文加连字符。
- 仓库名与项目根 `package.json` 的 `name` 一致。例外：目录名不是合法包名时，派生命令 `init-project.mjs --name <包名>` 允许包名异于目录名。

## 技能

- 技能目录名与 `SKILL.md` 的 `name` 完全一致。
- 小写英文、数字、连字符。不以连字符开头或结尾，不含连续连字符。
- 不超过 64 字符。
- 不使用下列保留名：`skills`、`docs`、`templates`、`scripts`、`test`、`evals`、`examples`、`node_modules`。

## 文件与目录

| 位置 | 格式 | 例 |
|---|---|---|
| 技能内目录与参考件、版式、子代理 | kebab-case 或中文名加扩展名，不加编号 | `判据摘要.md` |
| 流程文件 | `NN-名称.md`，NN 为两位序号，从 01 起连续 | `01-切分.md` |
| 脚本 | kebab-case，扩展名 `.mjs` | `validate.mjs` |
| 测试 | `<被测对象>.test.mjs` | `validate.test.mjs` |
| 测试夹具 | 与被测场景对应的 kebab-case 目录 | `broken-link/` |
| 评测用例 | kebab-case 或中文名，`.md` | `冒烟测试.md` |

## 编号

编号只在需要排序或引用时使用。

- 流程序号表示执行顺序。
- 编号在所在文件内独立计数，格式为类型前缀加两位数字。前缀只用下表取值：

| 前缀 | 用于 | 出现在 |
|---|---|---|
| `J-` | 技能运行时判据 | `references/` |
| `S-` | 策略 | `references/` |
| `K-` | 概念 | `references/` |
| `E-` | 参考件的来源依据 | `references/` |
| `C-` | 评测判据 | `evals/cases/` |
| `F-` | 功能需求 | `docs/产品/` |
| `A-` | 验收标准；派单验收标准（`04-文档与施工.md`），号段在派单文件与产品文档各自独立，不冲突 | `docs/产品/` |
| `Q-` | 开放问题 | `docs/产品/` |
| `D-` | 架构决策 | `docs/技术/` |
| `R-` | 风险 | `docs/技术/` |

- 跨文件引用写「文件名 的 编号」，如 `分段摘要.md 的 C-01`，不写裸编号：编号只在文件内唯一。
- 编号一经分配不复用。删除的条目保留编号，并在文件中标注已废弃。
- 不用编号表示优先级。优先级用单独的列。

## 中文

文件名可用中文，但同一目录内不混用中英文风格。文件名不含空格。

## 辅助内容

`辅助内容/` 不在任何仓库内，也不入库。它的两个跨项目目录各有自己的命名与保留规则，写在各自的 README 中，本文件不重复：

- `辅助内容/临时文件/`：草稿、调研、临时脚本。
- `辅助内容/测试目录/`：测试运行记录。

两边与仓库内文件重名时，以所在目录的 README 为准。

本文件规定技能内子代理的设计。模板见 `templates/skill/agent.md`，位置见框架树第一节。

## 位置与数量

- 子代理放在 `skills/<技能名>/agents/`，每个子代理一个文件。
- 文件名为角色的中文短名，如 `联网检索.md`。
- 只有确实需要独立上下文、独立工具权限或并行执行时，才设子代理。能在流程内完成的步骤，不设子代理。

## 文件内容

每个子代理文件固定包含以下小节，顺序不变：

1. 角色：一句话，写明负责什么。不写身份句。
2. 输入：字段、类型、是否必需、缺失时的处理。
3. 输出：结构化字段，顺序固定。
4. 可用工具：白名单。未列出的工具一律不得调用。
5. 调用方：哪个流程的哪一步调用它。
6. 步骤：祈使句，每步一个动作。
7. 停止条件。
8. 失败回退：失败时返回哪些字段，不得伪造结果。

## 调用与校验

- 只有流程可以调用子代理。子代理不调用其他子代理。
- 流程用相对路径指向子代理文件，不复制其内容。
- 流程检查子代理返回的每个必需字段。缺任一字段，不采信整个结果，并记录为失败。
- 子代理返回的字段值只作为候选，流程对关键字段做核对后再使用。

## 工具权限

- 白名单写在子代理文件中，不依赖调用方临时授权。
- 需要联网的子代理，白名单必须明确列出联网工具，并写明可访问的站点范围。

## 边界

- 本标准定义的是写作约定，不构成对宿主运行时能力的保证。

## 变更

- 改动 frontmatter 的可选键，视为破坏兼容，按 03 号标准升主版本。
- 改动目录分工，同次修改框架树与模板。

改动命名规则，同次检查已有文件是否违规，并在项目 CHANGELOG 中记录。

修改子代理的输入或输出字段，视为破坏兼容，同次修改调用方。
