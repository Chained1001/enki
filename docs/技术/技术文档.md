## 目标与约束

| 类型 | 内容 | 判据或原因 |
|---|---|---|
| 质量目标 | 切章零漏零误 | 五本样本书的已知章节索引（1393／914／1070＋6 番外／1023／11 章），`test/prepare.test.mjs` 对照 |
| 质量目标 | 校验器完备 | 完整产物退出 0；删任一段、列或行退出 1（PRD 的 A-10） |
| 质量目标 | 全自动不中途询问 | PRD 的 A-12，运行记录核对 |
| 质量目标 | 增量安全 | 只重做一卷时其他卷文件 mtime 不变（PRD 的 A-11） |
| 质量目标 | prepare 全程不调 LLM | 500 万字切章完成时间 ≤60 秒，脚本级计时 |
| 约束 | Node.js 24 及以上，脚本零外部依赖 | PRD 依赖表；`import` 外部包即违规 |
| 约束 | 原文不入仓库 | `.gitignore` 排除产物 `原文/`，提交钩子拦截 |
| 约束 | LLM 内容生成全部由宿主 agent 完成，脚本只做确定性工作 | 出错可归因：脚本错改脚本，内容错改流程或模板 |
| 约束 | 段名、表头、白名单、阈值只有一个机器来源 `contract.mjs` | 模板是给人读的副本，一致性由测试保证（D-01） |

## 上下文与边界

| 外部对象 | 用途 | 交互方式 | 不可用时 |
|---|---|---|---|
| 使用者（网文作者） | 提供原文路径，接收产物 | 对话（经宿主 agent） | 路径缺失时停止并询问（F-01） |
| 宿主 agent（Claude Code 类） | 执行 LLM 步骤：读流程、填模板 | 读 `workflows/`、`references/`、`assets/` | 无 agent 则只有脚本层可运行 |
| Node.js 24 | 运行确定性脚本 | CLI：`node scripts/…mjs` | 版本不足时脚本报错退出 |
| 文件系统 | 读原文，写产物目录 | 文件读写 | 无写权限时停止并说明 |

本项目不负责的部分：

- 拆解报告（书评式产物）：后期单独做。
- 跨书对比与素材入库：归 Sumeru。
- 原文抓取与格式转换（epub 等）：只接受 txt。
- 出版书独立变体模板：只做 `book_type=出版` 降级。

## 构建块

| 模块 | 路径 | 职责 | 依赖 |
|---|---|---|---|
| contract.mjs | `skills/book-breakdown/scripts/contract.mjs` | 段名、表头、白名单、分类目录、阈值、状态枚举的唯一机器来源 | 无 |
| prepare.mjs | `skills/book-breakdown/scripts/prepare.mjs` | 复制原文、宽正则切章、全局重编号、六类噪音剥离、作者的话归集、三级分卷检测、出版书判定、建目录树、骨架落位（从 contract 与模板生成固定产物骨架文件）、全书定量指标计算（写入文风骨架的定量指纹段）、写 manifest | contract.mjs |
| validate-output.mjs | `skills/book-breakdown/scripts/validate-output.mjs` | 逐文件校验段名、表头、幕覆盖、台账、行数、出处格式、索引对账，退出码 0/1 | contract.mjs |
| 结构化流程 | `skills/book-breakdown/workflows/` | agent 的分批处理与产物填写步骤 | assets/、references/、scripts/ |
| 模板 | `skills/book-breakdown/assets/` | 各产物的字段模板（人读） | 无 |
| 判据 | `skills/book-breakdown/references/` | 幕边界、主次判定、金手指的判定标准 | 无 |
| 测试 | `test/*.test.mjs` | 脚本与校验器的自动化验证 | contract.mjs、合成夹具 |

依赖方向：contract → prepare／validate（只读）；workflows → scripts（CLI 调用）＋ assets／references（读取）。脚本不得依赖流程，模板与判据不得依赖脚本。

## 运行时视图

| 场景 | 触发 | 步骤 | 产出 | 失败时 |
|---|---|---|---|---|
| 主流程 | 用户给出 txt 路径 | ① `prepare.mjs`：校验→复制→切章→清洗→分卷→建树→manifest → ② agent 按卷循环：分批摘要（≤20 章）落逐章记录 → 别名词典 → 卷纲/幕纲/伏笔台账 → 设定库 → ③ 全书层：全书大纲/文风/作者的话 → ④ `validate-output.mjs` → ⑤ 输出目录树与文件数汇总 | `<书名>_拆解/` 完整产物 | 见失败流程 |
| 失败流程①：输入不合格 | 路径不存在／非 txt／空／章节数 <3 | prepare 停止 | 失败原因 | 退出码非 0，不建目录（A-01/A-17） |
| 失败流程②：校验不过 | validate 退出 1 | 输出失败清单（文件＋缺哪段/列/行） | 修复指引 | agent 按清单修复对应文件后重跑 validate；其他文件不动（增量） |
| 失败流程③：批次中断 | 宿主会话中断 | 重跑时对比 manifest 受管状态块（D-12）与逐章记录行数，跳过已完成批 | 断点续跑 | 无 |

## 运行环境与部署

| 项 | 值 |
|---|---|
| 运行时 | Node.js ≥24（含完整 ICU，供编码检测转换） |
| 操作系统 | 不限；路径处理统一走 `path`/`node:url`，兼容 Windows 与 POSIX |
| 网络 | 脚本不需要；LLM 调用由宿主 agent 自带能力承担 |
| 文件系统 | 读：用户原文路径；写：产物目录（默认原文同级 `<书名>_拆解/`） |
| 发布方式 | 随技能仓库；技能安装后 scripts 经 CLI 调用 |

## 横切关注点

| 关注点 | 做法 | 位置 |
|---|---|---|
| 错误处理 | 退出码 0/1；错误信息中文，格式「文件＋问题＋缺什么」；脚本不抛裸栈给用户 | 各脚本 main 的 catch |
| 配置 | 全部取值集中在 contract.mjs（阈值、段名、白名单），无环境变量、无配置文件 | contract.mjs |
| 日志 | 处理日志记批号区间与章数（A-13）；完整运行记录写 `辅助内容/测试目录/`（不入库） | workflows 各步 |
| 安全 | 原文只读不改；产物 `原文/` 由 `.gitignore` 排除；脚本无网络、无删除操作（只创建与覆盖产物目录内文件） | prepare.mjs |

## 架构决策

| 编号 | 决策 | 理由 | 替代方案与代价 | 日期 |
|---|---|---|---|---|
| D-01 | 段名/表头/白名单/阈值以 `contract.mjs` 为唯一机器源；`assets/` 模板是人读副本，一致性由 `test/contract-consistency.test.mjs` 保证 | 双处手写必然漂移；解析模板 Markdown 当源太脆 | 只写 contract（人没得读）；模板为源（校验脆）；生成模板（模板语义写不进生成器） | 2026-10-22 |
| D-02 | 拆书脚本放技能内 `skills/book-breakdown/scripts/`，测试放仓库 `test/` | 随技能分发（01-技能写法的目录分工）；测试按 02-脚本与测试 走仓库 | 仓库根 `scripts/`：脱离技能分发，PRD 中 `scripts/…` 均指技能内路径 | 2026-10-22 |
| D-03 | 切章是纯规则宽正则，不用 LLM 兜底 | 五本样本书全部零误报；确定性可测；护栏「<3 章停」兜住识别失败 | LLM 兜底切章：不可测、不可复现、成本高 | 2026-10-22 |
| D-04 | 分卷三级信号按优先级：①「第X卷」独立行（唯一权威锚点）②章号重启检测 ③「(第N卷完)」尾标记回推；全部失效时全书为单卷并记入 manifest | 三级信号在样本书上互相验证（大奉①／诡秘②／道诡③） | 只信①：诡秘/道诡卷界错；内容语义判卷：不确定且贵 | 2026-10-22 |
| D-05 | agent 分批以卷为单位、每批 ≤20 章；每批完成即写入逐章记录（事务性：批不完整不落盘） | 上下文可控；中断可续；中间结果不丢（F-13） | 全书一次处理（上下文超限）；逐章一次一批（成本翻倍） | 2026-10-22 |
| D-06 | 逐章记录是过程层的唯一事实源：幕判定、出场统计、别名统计、断点续跑都从它派生 | 单一事实源，避免多处统计口径分叉 | 各步骤各自统计：口径漂移，对不齐账 | 2026-10-22 |
| D-07 | 出处格式「第 N 章＋引句」在 agent 写入时强制；validate 只做格式校验，不回源核对引句真伪 | 回源核对需再读原文，成本翻倍；格式校验已能拦裸条目 | 全量回源核对：成本不可接受，留人工抽查（A-19 形式） | 2026-10-22 |
| D-08 | 全自动，不设确认；非常规叙事书的「唯一真相」不自动裁决，产物显式「未决/双重记录」 | Q-05 裁决；裁决真假在文本层无解（道诡证据） | 人工确认节点：违背全自动目标 | 2026-10-22 |
| D-09 | 出版书由 `book_type=出版` 走降级目录树分支（无分卷总表/卷纲，幕＝原文单元），不复制第二套模板 | 一套模板两种装配；Q-16 裁决 | 独立变体模板：同系列形态漂移，证据不足 | 2026-10-22 |
| D-10 | 输入编码检测：非 UTF-8 时用 `TextDecoder('gbk')` 转码后写入产物副本，原文件不动，manifest 记 encoding；无法识别的编码停止 | 中文 txt 常见 GBK；Node 24 自带完整 ICU；原文只读原则 | 只收 UTF-8：拒掉大量真实文件；自动覆写原文件：违反只读 | 2026-10-22 |
| D-11 | 全书层的「核心冲突装置」在卷级循环之前先产出初版，作为后续所有卷的口径锚 | 先总后分锚定口径漂移（工程调研结论） | 纯自底向上汇总：卷与卷之间的装置口径不一致 | 2026-10-22 |
| D-12 | 断点续跑以 manifest 内受管状态块记账：批表（卷号、批号、章号区间、状态）与阶段表只由脚本写入；写盘走「临时文件→fsync→原子替换」；每批记输入区段哈希，源文件变更自动判缓存失效并提示重跑对应批 | 脚本独占写权防并发损坏；原子写防半截状态；源漂移检测防脏续跑（oh-story `manage_analysis_run.py` 的 `_progress.md`＋range_sha256） | agent 手改 manifest（无防护）；JSON 无原子写（中断即损） | 2026-10-22 |
| D-13 | 切章噪音阈值：疑似标题行 >100 字符判噪音丢弃；切出的短章 <10 字符并入前章；宽正则全失效时不降级造章，直接按护栏停止 | 丢弃阈值来自 StoryAgent `chapter_splitter.py` 实证；「全文单章」降级会静默产出错误产物，Enki 用 <3 章停（F-17）替代 | 无阈值：广告长行误判为标题；降级单章：假成功比失败更贵 | 2026-10-22 |
| D-14 | 汇总层守恒与红旗：分批摘要→卷级汇总时断言块数守恒（输入块数＝汇总记录数）；逐章记录的一句话事件字符数 ≥ 该章原文字符数记红旗警告 | 零信息丢失断言与「摘要长于原文＝异常」是廉价的脚本级 sanity check（BooookScore `chunk.py` 守恒断言、obook 红旗） | 不做：摘要层丢章/注水无法被机器发现 | 2026-10-22 |
| D-15 | validate 输出分两级：错误（退出 1，阻断）与警告（不阻断，列入报告）；总判定固定三档「通过／需修改／不通过」 | 校验失败≠全部作废：守恒红旗、弧内占比贴线等属警告级（QMAI 体检三档＋AI-NVA 质量债分级） | 单级错误：警告级问题逼停全书，或被迫静默放行 | 2026-10-22 |
| D-16 | 骨架先行：初始化（阶段 2）即从 contract＋模板生成全部固定产物的骨架文件（段名＋待填占位），卷纲/幕纲/主角文件夹/条目卡在各自判定点分批落位 | 用户给完路径立即看到产物全貌；填写与校验有明确靶子；消灭「边拆边猜产物形态」（PRD「产品流程」节骨架分级落位表） | 只建空目录（无骨架）：产物形态靠 agent 记忆，易漂移；全部最后生成（无过程可见性） | 2026-10-22 |
| D-17 | 进度状态模型分四层：阶段／卷／批／文件，记于 manifest 状态块；批为主进度口径，产物文件四态（骨架／已填写／校验通过／校验失败）；validate 分交付校验与进度校验两口径 | 进度查询读 manifest 即答（O(1)），不重读产物；部分产物有明确状态语义而非笼统「不通过」 | 只记批（阶段与卷不可见）；用文件 mtime 推断进度（不可靠、跨平台不稳） | 2026-10-22 |
| D-18 | 中断语义固定五档：暂停／取消＝优雅停于批边界、产物永不自动删除；继续＝prepare 重入幂等（已存在即对账续跑）；重拆＝旧目录改名归档后全新初始化；崩溃＝按未标记暂停恢复；批失败＝重试 1 次后停该卷即报 | 与「脚本无删除操作」的安全原则一致；重拆是用户明确授权，归档优于删除；静默跳过失败批是开源调研反面清单项 | 中断即作废重拆（浪费已完成批）；删除旧目录（破坏性、不可逆）；失败批静默跳过（QMAI 反面清单） | 2026-10-22 |
| D-19 | 批内允许分片落盘：每批 ≤20 章为上限，批内可按 5-6 章幂等写盘（只改本批行）；批粒度是进度单位，不是写盘单位 | spike 实证 19 万字单批整写有上下文溢出风险，分片幂等写既保安全又保进度语义 | 批压到 ≤10 章（进度记账翻倍）；整批一次写（溢出风险） | 2026-10-22 |
| D-20 | 分卷一级信号区分卷首锚点与卷末总结行：「第N卷＋总结/感言/致歉/感谢/记录/说明」类行按卷尾信号切卷，其余按卷首锚点；区间倒挂即弃 | spike 真书实证（绍宋的「第二卷总结 兼致歉信」被当卷首导致边界错一卷并产生倒挂区间） | 全部按卷首锚点（绍宋形态必错）；只信尾标记（大奉无尾标记） | 2026-10-22 |

## 质量属性与风险

| 属性 | 场景 | 判据 | 现状 |
|---|---|---|---|
| 性能 | 500 万字 prepare | ≤60 秒，计时 | 未测 |
| 可靠性 | 会话中断后重跑 | 已完成批全部跳过，产物无重复段 | 未测 |
| 可靠性 | 校验器完备性 | 删任一段/列/行退出 1 | 未测 |
| 可维护性 | 改一个段名 | 只改 contract 与模板两处，测试守护一致 | 未测 |
| 可移植性 | Windows／POSIX 路径 | 同一产物树在两平台一致 | 未测 |

| 编号 | 风险 | 影响 | 缓解 |
|---|---|---|---|
| R-01 | 幕边界判定质量不稳定（agent 判定） | 幕纲与卷纲对不上账 | 幕边界判据 J-01～J-05＋单卷 spike 先行验证（见 PRD 流程）；认知翻转点降级人工 |
| R-02 | 长伏笔漏检（跨度千章） | 台账不全 | 优先从复盘章反填（F-19）；卷纲埋收两列与台账互相钩稽 |
| R-03 | 百万字 token 成本超预期 | 全书拆解贵 | 分批以卷为单位可单卷重跑；快速模式兜底；成本在 spike 阶段实测 |
| R-04 | 盗版文本损伤（丢引号/水印/剥间隔号） | 文风与对话分析失真 | 清洗六类；残留损伤标注「文本质量受限」（PRD 假设表） |
| R-05 | 模板与 contract 漂移 | 校验与文档不一致 | D-01 的一致性测试 |
