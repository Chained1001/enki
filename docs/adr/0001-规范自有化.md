# 0001 规范自有化

## 状态

accepted

## 背景

`docs/规范/` 原先被当作上游 0.5.4 的副本：`test/standards.test.mjs` 逐字比对上游，规范正文以「与上游一致」为正确标准。这条路线有三个问题。

- 上游落后且不再权威：派生之后 `02-脚本、测试与提交.md` 已在本仓就地改过，逐字比对只能靠继续声明「这是偏离」来维持，改一处就要解释一处。
- 没有来源账：哪份标准借鉴了上游哪几条、偏离了什么、为什么偏离，只散落在提交信息里；上游更新时无法判断该不该跟。
- 门禁守错了对象：逐字一致只能证明「抄得一样」，不能证明本仓的规则自洽；上游本身没有本项目的错误码分层与产物契约。

## 决策

规范正文由本仓自持，上游降为参考实现，不构成权威。

- `docs/规范/` 的文件即正文。改规范不需要同步上游副本，走 PR 并在 `CHANGELOG.md` 的 `[Unreleased]` 记录。
- 新增 `docs/规范/来源.md`：逐份登记来源（上游／外部标准／本项目原创）、借鉴内容、偏离与理由；新增标准必须登记，改动标准同次更新登记。
- `test/standards.test.mjs` 从「与上游逐字比对」改为结构检查：文件名编号连续、首行格式正确、来源表覆盖全部标准文件。
- 上游只作参考：是否吸收上游改动由人判断，判断结果记 `CHANGELOG.md` 或本目录的 ADR，不自动跟随。

## 后果

- 上游更新不再自动传导到本仓；「上游这么写」不再是理由，理由要落在 `来源.md` 的「理由」列，可被复核。
- `来源.md` 成为规范之外的第二处账本：改标准漏登记会被 `standards.test` 报出。
- 结构检查只保证自有结构完整，不保证内容与上游一致；语义正确性回到 PR 审阅，不再由逐字 diff 代劳。
- 新建标准时先登记来源再写正文，否则测试变红。
