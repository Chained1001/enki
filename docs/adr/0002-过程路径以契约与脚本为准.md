# 0002 过程路径以契约与脚本为准

## 状态

accepted

## 背景

P0-2 之前，同一批过程文件在 PRD、流程文档与脚本里各有一套路径。

- 核心冲突装置：06 往全书大纲填初版、07 逐卷回填、09 再定稿，同一段被三个阶段各改一遍，实测留下「`## 核心冲突装置`」与「`### 装置段终稿`」两版并存的痕迹。
- 分卷片段：多卷并行时逐章记录、伏笔台账、别名词典要先写分卷片段，但路径一说放 `工作/` 顶层、一说统一到 `工作/增量/`。
- 裁决：出处核验的每批判裁只存在子代理返回值里，崩一批就全丢；要落盘又没有约定文件名。

路径写错的后果不是「不好看」，是脚本按名匹配不到：`merge-foreshadow.mjs` 的增量正则只认 `工作/伏笔台账-卷N.md`，契约的 `VARIABLE_FILE_RULES` 也只认这一形态；放到别处会被树校验判 `E_TREE_EXTRA`，或合并时静默漏掉整卷。

## 决策

过程路径以 `skills/book-breakdown/scripts/contract.mjs` 的白名单与脚本实际读取的路径为准，文档只引用，不复写第二套。

1. **装置**：06 初版落 `工作/增量/阶段06-装置.md`，07 回填落 `工作/增量/阶段07-装置-卷N.md`；只有 09 往 `故事底本/故事剧情/全书大纲.md` 的「核心冲突装置」段写一次定稿。
2. **分卷片段**：`工作/逐章记录-卷N.md`、`工作/伏笔台账-卷N.md`、`工作/别名-卷N.md`，一律 `工作/` 顶层；收口时逐章记录与别名由主线程按卷拼接，伏笔台账交 `merge-foreshadow.mjs` 合并重编号。
3. **裁决**：`工作/增量/裁决.json`，由主线程每批追加写；子代理只读，不写产物。

为什么分卷片段放 `工作/` 顶层，装置与裁决放 `工作/增量/`：

- 分卷片段是常驻过程文件（`工作/逐章记录.md` 等）的分卷形态，收口后要拼回同名主文件；契约与 `merge-foreshadow` 都只认顶层形态（Q-64 的实际口径），放 `增量/` 会让脚本找不到。
- 装置片段与裁决是只进不出的中间件：装置由 09 合并后改写进交付面，裁决只被读取、不拼进任何交付文件。把它们与常驻三文件分开，`工作/` 顶层的文件数公式才仍然成立。
- 不把整个 `工作/` 放行：白名单按名字收紧，新增一条规则才多一个合法名；否则 `E_TREE_EXTRA` 失去判别力（Q-55）。

## 后果

- 文档里的过程路径必须与契约一致，`test/process-paths.test.mjs` 守这个一致性；旧路径出现在文档里即变红。
- 分卷片段放错目录会被树校验拦下；`merge-foreshadow` 找不到增量文件时不会静默当作「没有伏笔」。
- 新增过程文件必须先加契约规则、再写流程文档，不能先写路径再补契约。
- 回填装置不再给全书大纲记 `filled`：文件状态由真正改它的人（09）记。
