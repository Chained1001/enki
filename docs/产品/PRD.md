本文件写给要改这个项目的人。读完应当能判断：拆书产出什么、什么不在范围内、怎样算做完。

## 背景与问题

网文作者想复用别人的结构，但拿到一本几十万到几百万字的小说时，缺一个能落地的拆解产物：章节摘要太浅，读完了还是不知道「这本书是怎么搭起来的」；笔记太散，写在新文件里，回头找不到。

现有 `book-breakdown` 只产出一份报告，解决不了「按层复用」的问题：想学全书结构、想学某一卷的节奏、想查某个设定，都得重新翻原文。

需要一套固定目录、固定文件名、可校验的拆书产物，让结构本身可被检索和比对。

## 目标

- 一本书一次拆解，产出一个 `<书名>_拆解/` 目录，目录结构固定。
- 四层剧情骨架齐全：全书大纲、分卷布局、每卷卷纲、每幕幕纲。
- 八份设定齐全，缺一份即视为未完成。
- 所有 Markdown 文件的段名可被脚本校验，不合格时明确报出文件与缺哪一段。
- 拆解完成后，用户只看目录就知道「这本书怎么搭的」，不需要回翻原文。

## 非目标

- 不做「拆解报告」（给读者看的书评式产物），后期单独做。
- 不做跨书对比、不做素材入库（属于 Sumeru）。
- 不做原文的全文检索或向量化。
- 不自动判断「写得好不好」，只还原结构。

## 用户与场景

| 角色 | 情境 | 目标 | 现在怎么解决 |
|---|---|---|---|
| 作者本人 | 读完一本想学的书，要拆它的骨架 | 拿到四层剧情与八份设定 | 手写笔记，散落各处 |
| 作者本人 | 写到某一卷卡住，想参考同类书的节奏 | 打开该卷的卷纲与幕纲 | 回翻原文，凭记忆 |
| 未来的自己 | 半年后想查某本书的某个设定 | 打开对应设定文件 | 找不到，重读 |

## 功能需求

| 编号 | 需求 | 优先级 | 验收 |
|---|---|---|---|
| F-01 | 技能启动后，第一步询问用户提供小说原文 txt 的路径；缺失时停止，不猜路径 | 高 | A-01 |
| F-02 | 校验原文可读、是 txt、非空；不满足时停止并说明原因 | 高 | A-02 |
| F-03 | 把原文复制到产物的 `原文/` 子目录，文件名保持原名 | 高 | A-03 |
| F-04 | 按 `<书名>_拆解/` 建立固定目录树：`原文/`、`故事底本/故事剧情/`、`故事底本/全书设定/` | 高 | A-04 |
| F-05 | 生成 `全书大纲.md`，含九个固定段名 | 高 | A-05 |
| F-06 | 生成 `分卷布局.md`，表头固定为 11 列 | 高 | A-06 |
| F-07 | 每卷生成一份 `卷纲/卷NN-卷名.md`，含固定段名 | 高 | A-07 |
| F-08 | 每幕生成一份 `幕纲/卷NN-幕NN-幕名.md`，含固定段名，且幕必须能对应到卷纲 | 高 | A-08 |
| F-09 | 生成八份设定文件：世界观、人物、人物关系、力量体系、势力与组织、地点、规则与铁则、物品与概念 | 高 | A-09 |
| F-10 | 提供 `validate-output.mjs`，逐文件校验段名、表头、幕覆盖，退出码 0/1 | 高 | A-10 |
| F-11 | 支持增量：可只重做某一卷或某一幕，不覆盖其他文件 | 中 | A-11 |
| F-12 | 拆解开始前，先展示目录树与预计文件数，等用户确认再动手 | 中 | A-12 |

优先级判据：不做则核心场景走不通＝高；走得通但有明显损失＝中；改善＝低。

## 验收标准

| 编号 | 标准 | 判定 | 证据位置 |
|---|---|---|---|
| A-01 | 未给路径时，回复含「请提供」与「txt」两个词，且不创建任何目录 | 通过 | `evals/cases/neg-no-input.md` 的 C-01 |
| A-02 | 路径不存在或非 txt 时，回复含失败原因，退出码非 0 | 通过 | `evals/cases/neg-bad-input.md` 的 C-01 |
| A-03 | 产物 `原文/` 下存在与源文件同名的 txt，字节数一致 | 通过 | 脚本核对 |
| A-04 | 产物目录树与契约完全一致，无多余文件 | 通过 | `scripts/validate-output.mjs` |
| A-05 | `全书大纲.md` 含九个段名，缺一即失败 | 通过 | 同上 |
| A-06 | `分卷布局.md` 表头 11 列，列名与契约一致 | 通过 | 同上 |
| A-07 | 每份卷纲含固定段名，卷号连续 | 通过 | 同上 |
| A-08 | 每份幕纲含固定段名，且卷 NN-幕 MM 能在卷 NN 的卷纲中找到对应幕 | 通过 | 同上 |
| A-09 | 八份设定文件齐全，文件名与契约一致 | 通过 | 同上 |
| A-10 | `validate-output.mjs` 在完整产物上退出 0，删任一段后退出 1 | 通过 | `test/validate-output.test.mjs` |
| A-11 | 只重做一卷时，其他卷的文件 mtime 不变 | 通过 | 人工核对 |
| A-12 | 动手前输出目录树与文件数，未确认前不写文件 | 通过 | `evals/cases/confirm-before-write.md` |

## 假设、约束与依赖

| 类型 | 内容 | 不成立时 |
|---|---|---|
| 假设 | 原文是纯文本 txt，章节标题可用「第N章」等形态识别 | 识别失败时停止并报告，不硬切 |
| 约束 | 不把整本原文写进仓库；产物目录中的 `原文/` 由 `.gitignore` 排除 | 提交前会被钩子拦下 |
| 依赖 | Node.js 24 及以上，零外部依赖 | 低于 24 时脚本报错退出 |
| 依赖 | 用户机器上能读写的输出目录 | 无写权限时停止并说明 |
