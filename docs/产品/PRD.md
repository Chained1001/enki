本文件写给要改这个项目的人。读完应当能判断：拆书产出什么、什么不在范围内、怎样算做完。

## 背景与问题

网文作者想复用别人的结构，但拿到一本几十万到几百万字的小说时，缺一个能落地的拆解产物：章节摘要太浅，读完了还是不知道「这本书是怎么搭起来的」；笔记太散，写在新文件里，回头找不到。

现有 `book-breakdown` 只产出一份报告，解决不了「按层复用」的问题：想学全书结构、想学某一卷的节奏、想查某个设定，都得重新翻原文。

需要一套固定目录、固定文件名、可校验的拆书产物，让结构本身可被检索和比对。

## 目标

- 一本书一次拆解，产出一个 `<书名>_拆解/` 目录，目录结构固定。
- 四层剧情骨架齐全：全书大纲、分卷布局、每卷卷纲、每幕幕纲。
- 七份设定与 `人物/` 目录齐全，缺一份即视为未完成；有名有姓的角色一人一个文件。
- 所有 Markdown 文件的段名可被脚本校验，不合格时明确报出文件与缺哪一段。
- 拆解完成后，用户只看目录就知道「这本书怎么搭的」，不需要回翻原文。
- **全自动**：用户给一次路径，之后不再打断、不再询问，直到产物通过校验或明确失败。

## 非目标

- 不做「拆解报告」（给读者看的书评式产物），后期单独做。
- 不做跨书对比、不做素材入库（属于 Sumeru）。
- 不做原文的全文检索或向量化。
- 不自动判断「写得好不好」，只还原结构。
- **不设人工确认环节**：没有「你先建骨架、我看看再继续」这一步。质量靠校验与出处标注，不靠中途点头。

## 产物结构

一本书产出一个 `<书名>_拆解/` 目录，结构固定。目录外的文件一律不属于产物。

```
<书名>_拆解/
├── 原文/                                  脚本建，交付
│   ├── <书名>.txt                          原文副本，与源文件同名同字节
│   └── 章节/
│       ├── 0001-第一章 标题.txt             每章一个文件，四位序号
│       └── 0002-第二章 标题.txt
├── 工作/                                  脚本建，过程产物
│   └── manifest.json                      章节表、字数、卷标题、输出路径
├── 故事底本/                               agent 填，交付
│   ├── 故事剧情/
│   │   ├── 全书大纲.md                     九段
│   │   ├── 分卷布局.md                     11 列表
│   │   ├── 卷纲/
│   │   │   └── 卷01-卷名.md                每卷一份，六段
│   │   └── 幕纲/
│   │       └── 卷01-幕01-幕名.md           每幕一份，五段
│   └── 全书设定/
│       ├── 世界观.md
│       ├── 人物/                          一人一文件，按主次分三档
│       │   ├── 索引.md                     姓名、主次、立场、首次出场、文件路径
│       │   ├── 人物关系.md                 关系表
│       │   ├── 主角/
│       │   │   └── 克莱恩.md
│       │   ├── 主要配角/
│       │   │   └── 老尼尔.md
│       │   └── 次要角色/
│       │       └── 值夜人甲.md
│       ├── 力量体系.md
│       ├── 势力与组织.md
│       ├── 地点.md
│       ├── 规则与铁则.md
│       └── 物品与概念.md
└── 拆解报告/                              待实现，本版不创建
```

| 路径 | 本版创建 | 产出者 | 数量 | 校验 |
|---|---|---|---|---|
| `原文/` | 是 | `prepare.mjs` | 1 份原文 + N 个章节文件 | 字节数与源文件一致 |
| `工作/manifest.json` | 是 | `prepare.mjs` | 1 | 章节数与实际文件数一致 |
| `故事底本/故事剧情/全书大纲.md` | 是 | agent | 1 | 九个段名齐全 |
| `故事底本/故事剧情/分卷布局.md` | 是 | agent | 1 | 表头 11 列 |
| `故事底本/故事剧情/卷纲/` | 是 | agent | 每卷 1 份 | 六个段名齐全，卷号连续 |
| `故事底本/故事剧情/幕纲/` | 是 | agent | 每幕 1 份 | 五个段名齐全，能对应到卷纲 |
| `故事底本/全书设定/人物/` | 是 | agent | 1 索引 + 1 关系 + 每个有名角色 1 份 | 索引行数与角色文件数一致，索引里的路径都存在 |
| `故事底本/全书设定/` 其余 | 是 | agent | 固定 7 份 | 文件名与契约一致 |
| `拆解报告/` | 否 | 后期 | 0 | 本版不检查 |

命名：

- 卷号、幕号各两位，从 `01` 起连续；卷号与幕号在文件名中不重复。
- 卷名、幕名优先取原文标题；标题含 `\ / : * ? " < > |` 时替换为 `_`。
- 章节文件名取章节标题，同样替换非法字符；四位序号从 `0001` 起（前言为 `0000`）。
- 角色文件名取角色名；重名时追加首次出场章号，如 `克莱恩-第12章.md`。

文件总数 = 2（大纲、布局）+ 卷数 + 幕数 + 7 + 1 索引 + 1 关系 + 角色数 + 原文与清单。一本 1000 章、4 卷、每卷 5 幕、120 个有名角色的书约为 2+4+20+7+2+120+2 = 157 份主要文件，另有 `原文/章节/` 下 1000 个章节文件。

## 用户与场景

| 角色 | 情境 | 目标 | 现在怎么解决 |
|---|---|---|---|
| 作者本人 | 读完一本想学的书，要拆它的骨架 | 拿到四层剧情与八份设定 | 手写笔记，散落各处 |
| 作者本人 | 写到某一卷卡住，想参考同类书的节奏 | 打开该卷的卷纲与幕纲 | 回翻原文，凭记忆 |
| 未来的自己 | 半年后想查某本书的某个设定 | 打开对应设定文件 | 找不到，重读 |

## 功能需求

| 编号 | 需求 | 优先级 | 验收 |
|---|---|---|---|
| F-01 | 技能启动后，第一步询问用户提供小说原文 txt 的路径；缺失时停止，不猜路径 | 高 | A-01 |
| F-02 | 校验原文可读、是 txt、非空；不满足时停止并说明原因 | 高 | A-02 |
| F-03 | 把原文复制到产物的 `原文/` 子目录，文件名保持原名 | 高 | A-03 |
| F-04 | 按「产物结构」节建立固定目录树，文件名与命名规则一致 | 高 | A-04 |
| F-05 | 生成 `全书大纲.md`，含九个固定段名 | 高 | A-05 |
| F-06 | 生成 `分卷布局.md`，表头固定为 11 列 | 高 | A-06 |
| F-07 | 每卷生成一份 `卷纲/卷NN-卷名.md`，含固定段名 | 高 | A-07 |
| F-08 | 每幕生成一份 `幕纲/卷NN-幕NN-幕名.md`，含固定段名，且幕必须能对应到卷纲 | 高 | A-08 |
| F-09 | 生成七份设定文件与 `人物/` 目录；人物一人一文件，按出场章数分主角、主要配角、次要角色三档 | 高 | A-09 |
| F-10 | 提供 `validate-output.mjs`，逐文件校验段名、表头、幕覆盖，退出码 0/1 | 高 | A-10 |
| F-11 | 支持增量：可只重做某一卷或某一幕，不覆盖其他文件 | 中 | A-11 |
| F-12 | 全自动执行：除 F-01 的路径询问外，不中途停下等确认；结束时输出目录树与文件数汇总 | 高 | A-12 |
| F-13 | 三级汇总，避免一次读完整本：章级记录 → 卷级纲要 → 全书大纲；每批不超过 20 章 | 高 | A-13 |
| F-14 | 每条结论标注章节出处（如「第 132 章」）；给不出出处的条目不写入 | 高 | A-14 |
| F-15 | `人物/索引.md` 一行一个角色，含姓名、主次、立场、首次出场章、文件路径；关系表两端角色都能在索引中找到 | 高 | A-15 |

优先级判据：不做则核心场景走不通＝高；走得通但有明显损失＝中；改善＝低。

| 编号 | 标准 | 判定 | 证据位置 |

| A-04 | 产物目录树与契约完全一致，无多余文件 | 通过 | `scripts/validate-output.mjs` |
| A-05 | `全书大纲.md` 含九个段名，缺一即失败 | 通过 | 同上 |
| A-06 | `分卷布局.md` 表头 11 列，列名与契约一致 | 通过 | 同上 |
| A-07 | 每份卷纲含固定段名，卷号连续 | 通过 | 同上 |
| A-08 | 每份幕纲含固定段名，且卷 NN-幕 MM 能在卷 NN 的卷纲中找到对应幕 | 通过 | 同上 |
| A-09 | 七份设定文件与 `人物/` 齐全；索引行数等于角色文件数；`.md` 文件名与契约一致 | 通过 | 同上 |
| A-10 | `validate-output.mjs` 在完整产物上退出 0，删任一段后退出 1 | 通过 | `test/validate-output.test.mjs` |
| A-11 | 只重做一卷时，其他卷的文件 mtime 不变 | 通过 | 人工核对 |

| A-13 | 处理日志里每批标注了章号区间，单批章数不超过 20 | 通过 | 运行记录 |
| A-14 | 每份剧情与设定文件中，条目均带「第 N 章」形式出处，无裸条目 | 通过 | `scripts/validate-output.mjs` |
| A-15 | 关系表每行两端的角色都出现在索引里，索引里的文件路径都存在 | 通过 | `scripts/validate-output.mjs` |

## 假设、约束与依赖

| 类型 | 内容 | 不成立时 |
|---|---|---|
| 假设 | 原文是纯文本 txt，章节标题可用「第N章」等形态识别 | 识别失败时停止并报告，不硬切 |
| 假设 | 单章长度在上下文预算内；超长章单独成批 | 单章超预算时按段落再切，并记录切分点 |
| 约束 | 不把整本原文写进仓库；产物目录中的 `原文/` 由 `.gitignore` 排除 | 提交前会被钩子拦下 |
| 约束 | 全自动，不设人工确认；质量由校验与出处标注保证 | 校验失败时输出失败清单，不静默通过 |
| 依赖 | Node.js 24 及以上，零外部依赖 | 低于 24 时脚本报错退出 |
| 依赖 | 用户机器上能读写的输出目录 | 无写权限时停止并说明 |
