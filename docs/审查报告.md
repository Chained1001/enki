## 结论摘要

**总体判断：这是一个设计意识明显高于实现完成度的项目。** 分层（contract → scripts → workflows → assets/references）是对的，「单一机器源＋人读副本＋一致性测试」在拆书类项目里属于少见的工程自觉；方法论也不是拍脑袋，`docs/产品/模板反推/证据/` 里五本真书的反推记录（约 168 KB）确实支撑了现有字段设计。测试 87 例全绿，`npm run validate` 退出 0。

**但它在三个地方同时失守，且都指向同一个根本原因：契约写了，闭环没做。**

1. **内容侧：模板与校验器互不认账。** 照 `assets/` 模板的字面形态填写，会被自家 `validate-output.mjs` 判错——已实测：世界观缺「一句话世界」段、专题缺 5 段、分卷总表带「（可选）」后缀触发 `E_COLUMN`，且受 `E_SOURCE` 管辖的 64 个字段标签中有 55 个（86%）不在豁免白名单，会被误判为「缺章节出处」。这不是风格问题，是**执行者按说明书操作必然失败**。

2. **代码侧：解析层无结构性护栏。** 正文句子被当噪音整行删掉（已复现 3 类）、目录页被算成章节、末章「（第一卷完）」产出 `startCh > endCh` 的自相矛盾卷区间、短章合并把 22 章的合法小书塌成 1 章后报「未识别到章节标题」。这些都不会报错，会**静默产出错书**。

3. **发布侧：v0.2.0 的内容根本没进 git。** `HEAD` 的 `package.json` 仍是 `0.1.0`，`contract.mjs`、`workflows/05-10`、19 份模板、`docs/技术/`、`docs/产品/产品流程.md` 全是 `??` 未跟踪，`CHANGELOG` 却已有带日期的 `[0.2.0]` 段。现在打任何 tag，发布的都是「切章＋摘要＋要素＋对账」四步老版本。

| 维度 | 分 | 一句话理由 |
|---|---|---|

## 第二部分：内容质量

### 2.1 模板与校验器互不认账（最严重）

已实测的四处结构性矛盾。**执行者照 `assets/` 模板填写，必然被 `validate-output.mjs` 判错**：

| 编号 | 模板 | 模板写的形态 | 校验器要求 | 实测结果 |
|---|---|---|---|---|
| M-01 | `世界观模板.md:16` | `- 一句话世界：…`（条目） | `SECTIONS.世界观` 含「一句话世界」，`headings()` 只收 `##`／`###` | `E_SECTION 缺少段名「一句话世界」` |
| M-02 | `专题模板.md:24-31` | 形态一把「定义与范围」等 6 段写成 `- xxx：` 条目 | 6 段是 `SECTIONS.专题` 的段名 | 实测 `E_SECTION` 连报 5 条缺段 |
| M-03 | `分卷总表模板.md:16` | 表头末两列带「（可选）」后缀 | `contract.mjs:57-58` 无后缀，`validate-output.mjs:174` 用**全等**比较 | 照模板重写表头即 `E_COLUMN` 阻断（已复现） |
| M-04 | 多份模板字段行 | `- 姓名（主名）：`、`- 归属势力：`、`- 获得章：` 等 | `E_SOURCE` 只豁免 20 类标签前缀（`validate-output.mjs:320`） | 受管辖的 64 个字段标签中 **55 个不在白名单（86%）**，被误判「缺章节出处」 |

`M-04` 已用完整探针确认：一份**完全正确填写、每条结论都带出处**的次要角色卡，仍被报 `1 条结论缺「第 N 章」出处。示例：姓名（主名）：李四`。

**为什么这是内容问题而非代码问题**：模板是「人读副本」，是 agent 唯一照着填的东西。模板说 A、校验器要 B，等于流程里埋了一个必踩的坑，且报错信息会把执行者引向错误方向（以为是「没写出处」，实际是「字段标签被当成结论」）。

**跨文件对不上账的具体场景**（填完必然出现）：

1. **幕数与弧数无法同时成立**。`幕边界判据 J-03` 与 `ENUMS.每卷幕数=[2,6]` 限制每卷 2–6 幕，但 `幕与节奏策略 S-02` 承认「同模板换内容即一级循环」，大奉式一卷可有 8–10 个小案件弧。填完要么把三案并成一幕（卷纲第 N 弧与幕纲对不上），要么幕数 8 触发 `W_ACTS`。而校验器只比对「弧行数＝幕纲文件数」，合并后账面照样平。
2. **别名与逐章记录互斥**。别名词典要求「揭示章之前不归并，标注揭示后归并：第 N 章」；逐章记录要求「出场人物经归并后填主名」。第 600 章揭示真名，前 599 章填什么？填主名即剧透；填别名则同一角色两个主名，J-01 的 60% 占比被拆散，主角可能被判成配角。
3. **章数三处各算各的**。分卷总表有「章数」、幕纲有「起止章」、manifest 有卷界，三者无任何校验。弧跨卷极常见，某幕起止章一旦越过卷界，三处之差无处说明。
4. **强化章无家可归**（M-07）。台账 F012：埋 88／强化 340／收 915，强化章 340 在卷纲和幕纲都塞不进去。

### 2.3 方法论：可用，但不足以做「分析引擎」

13 份 `references/` 的结构（J-/S-/K-/E- 四类、带依据）本身是好设计。问题在**可用性**与**覆盖度**。

**4 条判据明写「主观判断，由人核对」**，与 PRD「全自动、不设人工确认」直接冲突——这些规则在自动流水线里**永不生效**：

| 条目 | 原文 |
|---|---|
| 主次判定 J-05 | 「功能位修正…主观判断，由人核对」 |
| 主次判定 J-07 | 「同字异人与词形歧义核对…主观判断，由人核对」 |
| 幕边界 J-04 | 「认知框架翻转点当章不可判…降级人工回填」 |
| 章节识别 J-04 | 「标题行前后各有空行…人工核对」 |

注意 `docs/规范/01-技能写法.md:30` 恰恰**鼓励**这种写法（「写不出阈值时…写"主观判断，由人核对"」）。规范与产品目标在这里互相抵消，需要上层裁决。

**无法落地的典型条目**（给编号，附原因）：

| 条目 | 为什么执行者判不出 |
|---|---|
| 结构拆解 S-01 三幕反推 | 1:2:1 与「按卷分摊」并存，千章书第一幕到第几章无换算 |
| 结构拆解 S-03 鸿沟检测 | 落差无大小阈值，几乎每场戏都有微落差，全记＝全记 |
| 结构拆解 S-05 节拍对照 | 15 拍对 1000 章无尺度换算 |
| 幕与节奏 S-03 爽点循环 | 有周期章数无健康区间；断点归因必错 |
| 幕与节奏 S-04 章末钩分型 | 分四型不分强度，「危机」与「期待」孰强不可比，跨书不可比 |
| 幕与节奏 S-06 蓄势-爆发 | 「主角视角让渡聚集」无阈值，只能永远标「疑似」 |
| 设定提炼 S-01 复用性测试 | 出题人与答题人同一人，自问自答恒为真 |
| 设定提炼 S-09 专题槽位 | 「核心设定词密度高」无密度值 |
| 人物提炼 S-05 want-get | 未定义阶段切分，want 粒度不明 |
| 文风分析 S-04 潜台词密度 | 无计量单位（千字/对话轮/场景差一个量级） |
| 伏笔识别 S-01 五类信号 | 「命中即记」，唯一护栏是「判断不了不记」，台账必爆量 |

**读起来像废话的 3 条**（建议降级或删）：

- 人物提炼 S-09「金句锚：选既能检索又能定义这个人的原句…名言式引句优于描写式」——无判据、无阈值、不可证伪，「名言优于描写」是文摘偏好不是叙事判断。
- 要素判据 K-03「情节线：有起因、发展、结果的连续事件」——任何三段连续文字都能套，作为分类判据不产生区分度。
- 文风分析 S-06「叙述双轨：网文常见叙述句＋内心弹幕，记两轨配比」——「常见」＝几乎全样本成立；「配比」无单位无基准。

**方法论缺口（按对产物价值的影响排序）**：

| # | 缺什么 | 导致产物缺什么 |
|---|---|---|
| 1 | **开篇三章的判据**。F-24 要求四项深拆，13 份参考件里**无一件定义**这四项怎么判 | 最常被学的一块全靠 agent 自由发挥 |
| 2 | **钩子强度分级** | 章末钩只能标类型，无法比较「哪个钩更狠」，无法跨书学 |
| 3 | **爽点密度/期待感的量化基线** | 节奏只能定性描述，作者拿不到「多少章一个爽点」 |
| 4 | **结论→可复用写作指令的转化路径** | 拆完仍是「这本书发生了什么」，不是「我该怎么写」 |
| 5 | **金手指的代价-收益经济性** | 金手指模板有「代价与限制」段，但无「代价是否对等」的判据 |
| 6 | **配角功能位分类表** | 人物卡有「原型词/功能位」一格，无枚举无映射 |
| 7 | **题材差异化基线**（玄幻/都市/历史/悬疑） | 60%／30% 阈值被当通则，实际只在 5 本样本上验证 |
| 8 | **AI 拆书的幻觉控制** | 只有 S-09「宁缺毋造」一句，无抽样复核、无断言门槛 |

**内部冲突**：

- **「幕」有三种含义**：辞典 K-01 三幕（全书）、幕边界 J-01「幕＝卷内事件弧」、F-08 又要求幕数≡事件弧数——等于用同一件事自我校验。建议全书幕／卷内弧／弧内拍三分层加映射表。
- **编号跨文件重号**：`S-01` 在 7 个文件指 7 件事；`K-01` 在辞典是「三幕结构」、在要素判据是「人物」；主次判定判据还引用「要素判据 K-01」，指代链已断。规范 `03-命名.md:48` 本就要求「跨文件引用写「文件名 的 编号」，不写裸编号」——现有写法违反自家规范。
- **章节识别文档落后于代码**：`references/章节识别.md:11-13` 只认「章」、缺「回/节/幕/终章/番外」、标题 40 字硬上限；而 `prepare.mjs:45-47` 已覆盖回/节/幕/终章/番外，阈值是 100。**workflow 明确要求 agent 按参考件执行**（`01-切章.md:18`），文档缺口会直接变成切章缺口。
- **K-15 与 K-23 的信息差方向相反**：K-15「作者已知而读者未知」、K-23「角色/读者知情差异」表述不一致。
- **多处「标拖/节奏问题/工具人倾向」违反 PRD 非目标**「不作好坏判断，只还原结构」。

**证据强度薄弱**：多个阈值从单一样本推广成通则——60%/15%（诡秘、绍宋、龙族各单书）、2–6 幕（大奉 9/11）、钝收 2 章、均章长 2400→3500（仅重生）。`金手指判据 J-01`「每本书必有金手指｜样本 5/5」属过度概括，且**无扑街书负样本**，无法排除幸存者偏差。

### 2.4 快速模式已被冷落

`报告模板.md` 有三重证据说明它停在了结构化模式之前：

1. **自证**：「边界：按 Q-08 裁决保留为快速模式，**不再扩展**」——模板自己声明停止迭代，而结构化模式已到 v6。
2. **质量断层**：只有「章节摘要＋人物/设定/情节线/技法＋对账」，无全局章号、无卷幕层、无伏笔、无金手指、无出处格式（F-14）、无文风。同样一本 1000 章的书，快速模式产出的是一张 1000 行无结构摘要表，比逐章记录的八列还弱。
3. **脱离校验**：用 `####` 写四张要素表，而 `headings()` 只收 `##`/`###`，这四段对校验完全不可见；`productOf()` 也没有「报告」分支。

同时 `references/要素判据.md:22` 的依据写成「见 `../assets/报告模板.md`｜要素表｜证实」——**判据拿模板当证据**，形成自指闭环。

### 2.5 模板粒度

PRD 估算一本书约 461 份文件。`一人一文件、一条目一文件` 对百万字大书：索引承担了检索，尚可接受；但**物品、概念、次要角色**一文件严重过剩——这三类通常 80% 是「提及即止」的边缘条目，为一句话开一个文件，维护成本高于检索收益。建议改「一表多行＋关键条目单卡」。
