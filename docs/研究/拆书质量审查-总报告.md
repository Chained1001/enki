## 一、结论摘要

**这套技能包不缺结构，缺的是「判定」与「设防」。**

骨架层已达可交付水准：逐章记录十二列、四层叙事骨架、伏笔台账、文风定量指纹都是扎实的；绍宋 spike 的全书大纲、卷纲、幕纲、人物卡在抽查中拿到 4-5 分（1=套话，5=可直接仿写），逐章记录 433 行无缺无重、94% 含原文引号。**能做出好产物**。

问题不在「做不出好的」，在「做不出好的也没人知道」：

| 事实 | 数字 | 出处 |
|---|---|---|
| 契约覆盖的表面积 | 95 个表列中 43 列（45%）；卡片 52 个字段 0 覆盖 | 附件·模板 |
| 散文段 | 77 个，**唯一不设防的部分** | `validate-output.mjs:436-441` |
| 可机械判定的判据 | 24 条 J- 中 11 条全自动、6 条半自动、7 条靠感觉；含 61 条 S-（`拆解总策略.md:16` 行粘连使 S-07 在表格里不可见，故实扫 60）与 65 条复选框，共 150 项，可机械判定率 7% | 附件·方法论 |
| 带阈值的复选框判据 | 65 条中 0 条 | 附件·方法论 |
| 真实可恢复层数 | manifest 记 4 层，实际 2 层 | 附件·流程 |
| 伏笔编号悬空 | 283 处引用指向台账里不存在的编号（真悬空 261） | 附件·产物实证 |
| 出版书路径层级 | 四层压成两层（无卷纲、无分卷总表） | 附件·产物实证 |

三条贯穿全案的因果链：

**① 套话是被激励出来的，不是 agent 偷懒。** 表格列有契约、有校验，写错变红；散文没有契约，且 `validate-output.mjs:438`「散文不写章号 → 整行跳过」既不进分母也不报缺。任何理性的 agent 都会把功夫往散文里灌。**产物里体量最大的部分（77 段）恰好是唯一不设防的部分。**

**② 判定靠感觉，是因为章程允许了。** `拆解总策略.md:16` 的 S-06「逆用写作法」把**作者自查题**直接当**拆书判据**。作者写「读者会紧张吗」时心里有答案；拆书的人只读文本，同一句话不可回答。65 条复选框判据全部源于这条许可。

**③ 质量门守错了维度。** `test/references-depth.test.mjs:21-24` 断言「正文 ≥20 行」「总行 ≥80 行」——**体量**。所以 1228 行的 `人物提炼策略.md` 过关了，尽管它的 28 条判据无一带阈值。测试保证了文件够长，没保证内容能用。

## 二、审查维度与判据

### 2.1 总判据：可仿写性优先

「好用够用」拆成三条可检验标准，优先级递减：

| 判据 | 定义 | 为什么是这个优先级 |
|---|---|---|
| **可仿写性** | 作者不看原文、只读产物，能写出合格的一章 | 最高。前两条都是为它服务；它过不了，前两条达标也无意义 |
| 可判定性 | 两次独立拆解能得出同样的结论 | 中。不可判定的结论不可复现，也就不可信 |
| 覆盖面 | 成功网文的成功要素有没有落位 | 低。缺要素可以补，判定不了则补了也是套话 |

明确**不做**的：诊断型产物（对照自己已写的书找问题）。本版只服务仿写，但保留可对比的量化指标接口（文风定量指纹已是这个方向的雏形）。

### 2.2 五类对象，五组维度

不统一维度，因为模板、判据、流程、产物、脚本的失效方式不同。

| 对象 | 维度 | 深度 |
|---|---|---|
| **模板**（20 份） | ①够用性 ②必要性 ③可判定性 ④可填性 ⑤契约覆盖 ⑥耦合 ⑦冗余 ⑧**作者可用性**（必答，权重最高） | 字段级 |
| **方法论**（14 份） | ①可判定性 ②覆盖度 ③一致性 ④索引准确性 ⑤耦合 ⑥来源正当性 | 判据级 |
| **流程**（10 条） | ①视野 ②上下文规模 ③并行性 ④可恢复性 ⑤重复劳动 ⑥失败回滚 | 阶段级 |
| **产物**（2 份真书） | ①具体度 ②可仿写性 ③事实错误 ④完成度 ⑤跨书可比性 | 文件级 |
| **脚本**（11 个） | ①正确性 ②覆盖盲区 ③未引用常量 ④与文档一致性 | 脚本级 |

「作者可用性」是三份旧报告都没有的维度，但最贴近目标。它问的是：**假设你是网文作者，只看这一份产物、不看原文，你能仿写出多少？缺什么？** 每份模板都必须回答。

### 2.3 等级

四分档，每条结论必须落一档，不允许「待定」。

| 等级 | 含义 |
|---|---|
| **致命** | 导致产物错误或空话，必须改 |
| **重要** | 明显降低质量，本轮应改 |
| **建议** | 可改可不改 |
| **保留** | 看着可疑但实测有效，明确写「不动」及理由 |

不用 1-5 分：同一份报告里不同维度的分数不可比，而分档能直接决定「这轮做不做」。

### 2.4 证据颗粒度

- **问题条**：必须写 `文件:行号` + 可复核的原文片段。
- **改善条**：必须写清四项——改哪个文件的哪一节、改成什么、改完哪条测试会变红、需不需要新建测试。**做不到这四项的，降为「建议」档，不进改造清单。**

## 三、系统性发现

以下五条跨四份附件，单看任何一份都看不出。

### 3.1 表层指标与质量负相关

用同一套规则扫两份产物的全部断言行：

| 产物 | 断言行 | 带章号 | 带原文引句 | 标「推断/存疑」 |
|---|---|---|---|---|
| 绍宋（认真读过原文） | 1808 | 87% | 65% | 2% |
| 龙族1（批处理产物） | 924 | **97%** | 57% | 2% |

**龙族1 的带章号比例反而更高。** 所以「有没有出处」不能当深度闸门——格式齐全、内容空心的产物，恰恰是流程最擅长生产的。

闸门必须换成**引句不可替代性**：引句是否含只有读过原文才知道的具体名词（人名、地名、器物名、数字），而不是「气氛紧张」这类可替换描述。

用 `verify-quotes.mjs --json` 再切一刀，得到一个反直觉的对照：

| 产物 | 表格引句通过率 | 散文结论通过率 |
|---|---|---|
| 绍宋 | 246/386 = 63.7% | 166/262 = 63.4% |
| 龙族1 | 265/299 = 88.6% | 97/110 = 88.2% |

**散文的引句质量与表格几乎相同**（差 0.3-0.4 个百分点）。所以散文的问题不在「写得虚」，而在**核算方式**：`validate-output.mjs:438` 让不带章号的散文整行 `continue`，它既不进分母、也不报缺。散文不是写得差，是**根本不参与记账**——这比写得差更危险，因为无从统计。补 `W_PROSE` 不是为了抓差内容，是为了让这部分内容进入账本。

**但补的时候要小心误伤。** 绍宋 96 条 `suspect` 里，相当一部分是合法的摘要式标签：

```
卷01-第一卷.md:14  「穿越者的现代常识 vs 乱世现实」
卷03-卷03.md:14   「财政—战马—北伐」
```

这类行本来就该是提炼，不该回源。所以 T1（散文进账）与 T18（引句不可替代性）必须共用同一套豁免规则：**带引号的才是断言，不带引号的是标签**。把两者混在一起统计，得到的比例没有意义。

### 3.2 视野与判据错配

`workflows/07-卷循环.md:30-31` 规定**全卷批次完成后才做幕判定**。判幕的 agent 手里只剩十二列逐章记录，早期批次的原文早已滚出上下文。更关键的是第 31 行：

> 「若某幕结论依赖的章摘要质量不足，**只允许回读该章原文补摘要，不重做整批**」

**流程在禁止回读原文。** 而「幕」恰恰最需要原文：哪一章是开启锚、五拍是否俱全、人物弧的转折点在哪——十二列摘要里没有。这就是套话的机械成因：**判跨章的东西，却只给局部视野，还禁止补视野**。摘要的摘要，每降一档衰减一次，到全书大纲与人物卡时只剩骨架。

### 3.3 页码齐备而抽屉空着

`contract.mjs` 自称唯一机器源，实际管辖不到一半表面积。而缺少落位的判据共 13 处，最刺眼的三条：

- `主次判定判据.md:11,17` 要求「口径差异写入**索引头注**」——没有索引模板，也没有头注机制，`assets` 中「头注」零命中。
- `主次判定判据.md:18` J-08 说「可标『J-01 边缘』」——`人物索引` 没有备注列。
- 辞典把「期待感」（K-14）与「情绪兑现」（K-16）称为引擎，`assets` 里这两个词**零命中**。

判据在要求 agent 写到不存在的地方，agent 只能就近塞进散文，散文又免检。

### 3.4 可恢复性的第 3 层是假的

绍宋 `manifest.files` 实测 `{done:434, skeleton:26, filled:1}`，共 461 项。但那 26 个 skeleton **全都是已填成稿**（6 专题、大纲、台账、开篇、世界观、金手指、文风、别名词典、逐章记录、5 索引、人物关系、分卷总表、5 卷纲），文件里无「（待填）」残留。

同时 `validate --mode progress` 报「文件已填 61/61，批次 24/24」——它是从**文件文本**判断的，不读 manifest。

两套账互不相干，且都自洽。真实可恢复的只有两层：源 sha256 是否变更、批是否 done。**「哪些产物已写完」这一层不存在。**

### 3.5 骨架先行暴露的是空框架

`D-16` 的设计意图是「用户给完路径立即看到产物全貌」。实测《长安的荔枝》prepare：

```
23 个目录中 23 个为空
32 个文件（23 个骨架 md + 7 章原文 + manifest）
```

五集合的 19 个分类子目录（门派、家族、国家与政权…）在卡落位前全是空目录。用户看到的是**一个空框架**，不是「产物全貌」。

同时 `validate-output --mode progress` 在骨架阶段的表现自相矛盾——**退出码 0，汇总说 0 个错误，详情却逐条打印「错误」**：

```
data.errors = 0        ← 汇总
problems: 6 条，其中 severity=error 的 5 条全是 E_INDEX   ← 详情
错误 [E_INDEX] 故事底本/全书设定/人物/索引.md: 集合「人物」为空
错误 [E_INDEX] 势力与组织/地点/物品/概念 同样报错
```

根因在 `validate-output.mjs:477`：`if (mode === 'progress' && ...) errors.length = 0` 把**计数**清零了，但 `problems` 数组原样返回，CLI 又按 `severity` 逐条打印（`:586`）。于是同一份结果有两个说法，使用者看到满屏「错误」却被告知「错误 0」。

这是「两套账」在本项目里的第三次重现（前两次是 `manifest.files` 与实际文件、`validate --mode progress` 与文件文本）。骨架阶段空集合本不该算错误，但这要靠**降级为警告**做到，不能靠把计数器清零。

### 3.5b 一个真实存在、却零检查的维度

用「上一幕出口情绪 vs 本幕入口情绪」对绍宋 34 份幕纲的 33 个相邻幕对跑一遍：

| 结果 | 数量 | 占比 |
|---|---|---|
| 断点（出入情绪不一致） | 22 | **66.7%** |
| 连续 | 11 | 33.3% |

断点类型分布：扬→震荡 8 次、扬→抑 6 次、抑→震荡 3 次、抑→扬 3 次、震荡→扬 2 次。

这些断点里有相当一部分是**故意反转**——「抑→扬」正是爽点兑现点。所以不该报错，该报**待说明项**：要求该幕「幕定位」段写明「刻意反转」及理由，写明即消警。

这条的意义不在断点多，而在于：**现流程没有任何一处会检查它**。幕纲逐份看都很漂亮（抽查 4-5 分），幕与幕之间接不接得上，从来没人问过。这是「单文件质量高、整体不可用」的典型位置。

### 3.6 不可回滚的第一名是没有工具

伏笔台账要求全局连续编号（`07:33`），又允许分卷片段后合并重编号（`07:42`）。实测台账 241 条（F001–F241 无缺号），而卷纲与 34 份幕纲残留 **283 处**旧片段编号（`F1-01`、`F3-04`、`F4-06`…），台账中一个都不存在。其中 22 处可由台账补注里的换算表解出，**真悬空 261 处**（147 个唯一编号）。

根因不是 agent 疏忽：`scripts/` 下**没有任何重编号或引用同步工具**。改一处要同步 241 行 + 283 处引用（真悬空 261），靠人眼必错。同类问题还有首现章三写三错（别名词典、人物索引、人物卡各写一遍，刘錡实测三处都写 239，原文实为 197）。

## 六、验证方案

改造完成后用两本书验证，不拆全书。

### 6.1 样本与范围

| 书 | 角色 | 范围 | 体量 | 成本 |
|---|---|---|---|---|
| 《长安的荔枝》 | 全书全链路 | 6 单元全拆，跑 05→10 | 9 万字 / 5.4 万 token | 单会话可容 |
| 《大奉打更人》 | 网文长书 | 卷1 前 40 章 | 约 10 万字 / 62k token | 分批可容 |

选这两本的理由：长安是**唯一能一次装下整本书**的样本（5.4 万 token），可以验证端到端全链路与全书层聚合——此前从没有过（龙族1 只有 12 单元 11 幕，绍宋只跑了 1 卷）。大奉是标准网文，卷1 前 40 章正好覆盖「京察风云」卷开篇到第一个大案收束，能同时看到开篇三章、一个完整幕、伏笔埋收。

合计约 12 万 token，比拆一本大奉全书（200 万 token）省 94%。

**前置障碍（实测发现）**：`prepare.mjs` 目前**没有 `--range` / `--chapters` 选项**，对大奉执行时必切出全部 916 章、48 批。要真正「只跑前 40 章」，有两条路：

- (a) 给 `prepare.mjs` 加 `--chapters 1-40`，只切该区间（需同步 manifest 的 chapterCount 与批次表，成本中）；
- (b) 不改脚本，跑完后只处理批 1-2，其余标 `pending` 停在此处（零改动，但产物目录里会躺着 916 章的原文，浪费磁盘不浪费 token）。

推荐 (b) 用于本轮验证——**token 成本只取决于实际读了多少章，不取决于切了多少章**。`prepare` 只切章不调模型，916 章的切线成本是秒级、零 token。若验证通过并决定把大奉纳入常规回归，再考虑 (a)。

### 6.2 验证维度与通过标准

| 维度 | 怎么判 | 通过标准 |
|---|---|---|
| 端到端跑通 | 05→10 无中断完成，`validate-output` 退 0 | 一次通过，无需人工介入 |
| 可仿写性 | 反向测试：没读过原文的子代理据产物仿写一章，与原章对照 | 结构位、钩型、信息投放顺序三项至少对上两项 |
| 深度 | 引句不可替代性比例 | 长安 ≥ 70%，大奉 ≥ 60% |
| 断点续跑 | 中断后重跑，已完成批全跳过 | 产物无重复段，manifest 与实际一致 |
| 视野分级 | 幕纲是否重读了本幕原文 | 抽样 3 幕，幕纲引句必须在原文可验 |

### 6.3 两项成本实测

- 长安：单会话总输入，应与 5.4 万 token 同量级（含判据加载）。
- 大奉 40 章：分批 2 批，记 `cost.mjs --record`，与 `--report` 的确定性下界交叉核对。

## 八、审查方法与边界

### 8.1 方法

- **静态审计**：逐文件读，逐字段/逐判据/逐流程比对契约。
- **实测复核**：所有关键数字自己跑过——`detectChapters`/`detectVolumes`/`detectBookType`、`cost.mjs --report`、`validate-output.mjs --mode progress`、`verify-quotes.mjs`、逐章记录列统计、manifest 状态分布、死常量引用计数。
- **交叉验证**：四名独立撰写者分别负责模板、方法论、流程、产物实证，结论冲突处以实测为准。两处口径差异已在各附件内说明，不是矛盾：
  - **伏笔编号**：294（`F\d-\d+` 正则全量命中）／283（台账外引用数）／261（扣掉换算表可解的 22 处后的真悬空）／122（去重后的唯一编号数）。四个数各有定义，都在说「台账与引用已经对不上」这一件事。
  - **幕际情绪衔接**：流程附件按前缀归一算得 22/33 = 66.7%，产物实证按自己的解析口径算得 69.7%，两者都远高于「偶发」，结论方向一致。

### 8.2 边界

- 未做的实测：反向仿写测试（需改完代码才能跑，属验证报告）、大奉全书拆解、改造后的 A/B 对比。
- 未覆盖的对象：快速报告模式（`workflows/01-04`）本轮标「暂不验证」；`evals/cases/` 未审。
- 环境教训：本机 `pwsh` 为 PowerShell 5.1，`Get-Content` 按 ANSI 解码 UTF-8 会算错行数（如 `主次判定判据.md` 报 19 行、实为 34 行）。本报告全部行号用 `read` 工具或 Node 按 UTF-8 复核，`Get-Content` 得到的行号一律不采信。
