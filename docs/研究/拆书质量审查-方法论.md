## 一、判据与等级

### 1.1 六维度

| # | 维度 | 问法 | 不合格的表现 |
|---|---|---|---|
| ① | 可判定性 | 有阈值吗？两个人各自读文本，能得出同一个结论吗？ | 判据是「读者会紧张吗」这种问句，答案取决于读者的心，不取决于文本 |
| ② | 覆盖度 | 从「为什么读者追下去」倒推，该有的维度有没有 | 结构骨架充分、留存机制空白 |
| ③ | 一致性 | 同一概念在库内只有一套口径吗 | 钩型两套枚举、情绪两套取值 |
| ④ | 索引准确性 | `索引.md` 的起止行指向的那一节，真的是那一节吗 | 末节止行统一 +1 |
| ⑤ | 耦合 | 判据得出的结论，有没有字段承接 | 判据要求「标 J-01 边缘」，人物索引没有备注列 |
| ⑥ | 来源正当性 | 搬运件该不该搬？搬了有没有做「结论→字段」映射 | 整节搬运逐字保留，`assets/` 里零命中 |

### 1.2 最高判据

**可仿写性**：作者不看原文、只读产物，能写出合格的一章。

其余五维都是为它服务。不可判定的判据产不出可仿写的产物——它产出的是一句读起来像结论、落地时什么也没约束的话。

### 1.3 四分档

| 等级 | 含义 | 处置 |
|---|---|---|
| 致命 | 导致产物错误或空话，必须改 | 进改造清单，本轮做完 |
| 重要 | 明显降低质量，本轮应改 | 进改造清单，可排后 |
| 建议 | 可改可不改 | 进改造清单，标「本轮可跳」 |
| 保留 | 看着可疑但实测有效，不动 | 写「不动」及理由，进「不改的」一节 |

每条结论必须落一档，不留「待定」。

### 1.4 证据颗粒度

- **问题条**：写 `文件:行号`，附可复核的原文片段。行号用 `read` 工具或 Node 按 UTF-8 复核——本机 `pwsh` 5.1 的 `Get-Content` 按 ANSI 解码 UTF-8 会算错（`主次判定判据.md` 报 19 行，实为 34 行）。
- **改善条**：四项齐全——改哪个文件的哪一节、改成什么、改完哪条测试变红、要不要新建测试。缺任一项降为「建议」，不进改造清单正文。

### 3.1 `索引.md`（91 行，工具，脚本生成）

- ③一致性：无内部冲突。

### 3.15 系统性观察

四条跨文件结论，单看任一份都看不出：

1. **判据件（4 份 `J-`）耦合远好于策略件（5 份混合件）。** 原因在来源：判据件为本工具自写，每条带真书实证；5 份混合件的正文是整节搬运（`结构拆解策略.md:9`、`幕与节奏策略.md:9,91`、`伏笔识别策略.md:9` 均明写「正文逐字保留，未压缩、未改写」，`人物提炼策略.md:1217`、`设定提炼策略.md:608` 以「知识库出处（本次整节搬运）」标注），搬运时**没做「结论→字段」映射**。
2. **质量门守错了维度。** `test/references-depth.test.mjs:21-24` 把 5 份文件列入 `PORTED` 进度账，强制含「机制/判据/常见错误」三类小节——保住了深度，没保住可判定性与可落位性。它断言的是正文 ≥20 行、总行 ≥80 行，即**体量**。所以 1228 行的 `人物提炼策略.md` 过关了，尽管 28 条判据无一带阈值。
3. **不可判定的判据有共同语法。** 65 条复选框里，凡是含「读者」「读者会……吗」「有没有……太多」的，全部不可判定；凡是含「章号」「次数」「比例」「枚举值」的，全部可判定。这条语法可以直接当改写规则（§5.2）。
4. **耦合良好的部分可作改造范式。** 主角三要素→`人物卡模板.md:27-29`；伏笔多层兑现→`伏笔台账模板.md:29`；面具与真相→`人物卡模板.md:54-56`；金手指八类枚举→`金手指模板.md:18-20`；换图→`分卷总表模板.md:16`；信息延迟三手法→`文风模板.md:24-26`；空间规则→`地点卡模板.md:20`。七处的共同点：**结论在模板里有一个专属字段**。

### 4.2 靠感觉判据的共同缺陷

七条靠感觉的 `J-` 归三类病，不是七种病：

| 病 | 判据 | 病在哪 |
|---|---|---|
| **主语错**：把「读者有无感觉」当判据 | 幕边界 J-05（聚集）、主次 J-05（功能位） | 「聚集」的主体是读者注意力，不是章号；「功能」是叙事功能，不是文本事实。换主语即可判 |
| **无锚点**：判据成立靠人认一个未定义的对象 | 幕边界 J-01（双锚）、幕边界 J-02（五拍归属）、主次 J-07（同字异人） | 弧界的「锚」、五拍的「这一章属于哪拍」、身份的「验证」都没有可查的落点 |
| **不可证伪或自认主观**：判据的结论不承担风险 | 金手指 J-01（必有金手指）、幕边界 J-04（认知翻转点不可判） | J-01 找不到也判「无」，任何结果都不违反它；J-04 直接自称不可判 |

三类的改法各不相同：主语错的换主语（§5.2 的统一形式）；无锚点的补锚点（把「锚」定义成结算类章的特征词、把「身份冲突」定义成字段不相等）；不可证伪的改成记录句（「默认存在，核对后仍无证据则记『无』并写核对章区间」）。自认主观且结论是降级处理的（J-04）不必改，见 §7.5 N-01。

底稿「靠感觉判据」列了 8 条，其中第 8 条落在 `要素判据.md:11,13` K-01/K-03（「有行动」「连续事件」无计量口径）——是定义件不是判据件，因此不计入 24 条 `J-` 的分布，单独见 §3.6。

**② 「改写」不等于「加阈值」。** 20 条里有 12 条改完仍不可脚本复现（靠人读文本填枚举或计数），它们的合格标准是「第二人能复核」，不是「脚本能算」。把「可判定」误解成「可脚本化」，会导致为了上脚本而把判据做浅——`文风模板.md:38` 的 top-3 偏离章就是这种妥协的产物（能算，但算的不是显著性）。

**③ 移出会让 references 变短，但不许让深度变短。** `test/references-depth.test.mjs` 的三断言（机制/判据/常见错误）在移出后仍有 5 份文件要过。移出的是「判定动作」，正文的机制与反例留着——它们解释的是「为什么这样写有效」，对拆书者的价值是理解而不是判定。

### C4 主次档位区间重叠

### C5 幕的三套粒度口径

### 6.8 六处冲突的形态分类

同是「两套东西」，「硬冲突」的成因不都是同一类。分错类会开出错的药。

| 成因 | 冲突 | 处置形态 |
|---|---|---|
| **引用失效**（判据指向不存在的常量） | C3（15% 阈值不存在） | 补常量（不是删判据） |
| **口径错位**（把 A 口径的数值当 B 口径用） | C2（存储截断 40 写成识别阈值） | 改判据服从实现 |
| **枚举分叉**（同一维度两套取值域） | C1（钩型五类 vs 四分） | 删一套留一套 |
| **粒度混淆**（不同层次的东西被当成互斥） | C6（逐章方向 vs 幕内峰值强度） | 两层并存＋映射，不删 |
| **缺优先级**（同一区间被多条同时覆盖） | C4（55-60% 三覆盖） | 定顺序，不改区间 |
| **适用范围未分层**（判据默认一种书型） | C5（幕的三套粒度） | 分层＋把例外前置为第一分支 |

六类里只有 C1 是「必须删一套」的；C2/C3/C4/C6 都不删东西——它们的病在口径、引用、顺序、层次，删了会连带丢掉实证（C3 的 15% 有绍宋与龙族两份实证）。C5 不删但分层。这一条是裁决时的判断准则：**先问冲突是「重复」还是「错位」，重复删，错位修。**

### 6.9 裁决的一致性检查

裁决完要能通过三条自查，任一不过说明裁决有两套：

1. **契约侧唯一。** 六条裁决里有四条（C1、C3、C6 与 C2）触及 `contract.mjs`。改完 `ENUMS` 里每个键的取值域只有一套。
2. **模板侧可落。** 裁决后的每条结论能在 `assets/` 找到字段，否则进 §7.3 的「删判据」或「内部记账」。
3. **测试侧可红。** 每条裁决有一个会先红后绿的断言（§7.1「新建测试」列）。做不到的，说明这条裁决只是文字统一，没改变行为。

### 7.6 存量白名单（M-01 的豁免机制）

M-01 的新质量门一上线就会把 5 份混合件（带复选框的那 5 份，共 65 条）里的 45 条待移出项全部判红。本轮不可能同次改完，所以白名单不是可选项——没有它，M-01 只能两种结局：要么被回滚，要么被改成只查新文件（等于不查）。

**机制**（写进 `test/references-judgement-density.test.mjs`）：

```js
// 存量豁免：只允许按「文件 → 行号数组」逐条豁免，不接受整份豁免。
// 每条豁免必须带 issue，且 issue 的标题须含该文件与条目数（防一条 issue 罩住全部）。
const WAIVERS = [
  { file: '设定提炼策略.md', lines: [212, 461, 462, 533], issue: 0 },
]
```

三条硬约束：

1. **不许整份豁免。** 只能按行号数组豁免。整份豁免会让一份文件永久免检——那正是当前 `PORTED` 清单干的事（`test/references-depth.test.mjs:21-24`：不在表里的文件不受约束）。
2. **每条豁免指向一张 issue，且 issue 标题可机器核对。** 形如「`设定提炼策略.md`：16 条复选框改写」，标题含文件名与条目数。测试读 `WAIVERS` 时若 `issue` 为 0 或与行号数组长度不符，直接失败。
3. **豁免有到期条件。** 豁免条目对应的 M- 条目完成时必须同次从 `WAIVERS` 删除；删的时候测试自然转绿，不需要再改断言。若完成 M- 后忘记删，测试仍绿——所以加一条反向断言：`WAIVERS` 里任何一行若已经不匹配 `- [ ]`（即已被改写或移出），该行必须从 `WAIVERS` 删除，否则红。这条断言让白名单只能变短、不能变长。

白名单的初始内容就是 §5.3 的 45 条，分 5 张 issue 承接（每份文件一张），与 M-02 的分组一致。
