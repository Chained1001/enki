# 审查改造清单落实核查

## 这份文件是什么

2026-10-25 对 `docs/研究/` 五份审查报告的改造条目做了一次逐条核查：每一条都去代码/文档里找证据，找不到任何证据的记为「未落地」。

- `docs/研究/` 下的五份报告是**问题描述**，不当落地证据。
- PRD 与 CHANGELOG 只作为「错误码已登记」「行为已发布」的旁证。
- 核查只读，不改任何文件。

为什么要核查：v0.3.0 的 12 张子工单全部关闭，但子工单是按**主题**拆的，不等于审查报告的每一条都被覆盖。关单时若不核对，很容易把「主题做完了」当成「每一条都做完了」。

## 一处已修但值得记的教训

`validate-output.mjs` 的 `CARD_FIELDS.人物` 曾用合并标签「原型词/功能位」，而模板在 #20 已拆成两行。**每一张按模板填的配角卡都会被报「缺 1 个字段标签」**，而测试夹具恰好写的是旧的合并写法，所以测试全绿。修法见 `c484ca8`：清单拆开、夹具改正、`CARD_FIELDS` 提到顶层导出，并补两条方向相反的用例（清单→模板防误报，模板→清单防漏检）。

只建一条是不够的：删掉「功能位」时，「清单里每个标签都能在模板找到」照样通过——删掉的标签不在清单里，自然没得查。反向用例才是拦住漏检的那一条。

## 两条的最终归属（2026-10-25 复核）

**M-09**（方法论 17 条之一）与总报告决议 12 曾被当成冲突，上轮按「两者并不冲突」处理，**只做对了一半**。

C6 裁决要求两件事：强度词收进契约，**并且**给四行映射。上轮只做了第一件。C6 的理由原话是「库里没有映射，读者无法从『扬』推出『爽』，也无法从『爽』反推逐章取值」——这句话指出的缺口，上轮原样留下了。

现两件都做，并把「不做映射」落实为**不拿映射当判据**：

- 四行对照写进 `幕纲模板.md`，注明「是解释不是判据，不承担判定」
- 校验器只查峰值取值是否在 `ENUMS.峰值强度` 内，不拿对照表判定任何东西
- 决议 12 的实质要求（情绪列只有扬／抑／震荡三值、爽燃虐喜不写入那一列）保持不变

也就是说，冲突的不是「做不做映射」，而是「映射能不能当判据」。这个区分上轮没说清楚，现在写进契约注释与模板。

**C-03**（模板 25 条之一）上轮被刻意压着没做，理由是「必须和写入器一起发，否则会出现一列没人填的空列」。本轮补齐：

- `volume-stats` 的 `perVolume` 增 `sharpDensity` 字段（算不出给 `null` 不给 `0`）
- 分卷总表 15 → 16 列，「爽点密度」在「字数与均章长」之后
- `volume-stats --write-total` 把每卷密度写回总表，只改该格；表头不符退 1 拒写
- `09-全书层` 改成「先跑脚本写密度，再人工填叙述列」

写这一条时挖出一个**一直存在但没人受影响**的 bug：`volume-stats` 的占位判定是按行的（「任一列还是占位就丢整行」），而 agent 是逐列填的——「爽点已填、钩型未填」的章会被整行跳过，密度分母漏算且产物上看不出少了。原来的三项统计都不依赖分母，所以一直没暴露。现改为按字段判，三列全空才丢行。
- 做完一条就把那一行删掉；这份文件是账，不是历史。
- 一类、二类优先：前者是「承诺过但没防住」，后者是「两处说法相反」。
