# book-breakdown

## 何时使用

**只由用户显式调用，不做模糊意图识别。** 下列情形视为显式调用：用户点名 `book-breakdown`（或「拆书技能」「用拆书技能拆」），或明确要求按本技能的一套流程拆整本小说。

以下情形**不自动触发**，即使输入看起来像：

- 用户只给了 txt 路径并说「看看这本书」，没有点名本技能——先问是否要拆解，得到确认再进入。
- 用户问「这本书好不好看」「文笔怎么样」——这是评价需求，不是拆解需求。
- 用户只要单章分析、要写续写、要联网抓取——均不适用。

显式调用后仍需满足：

- 用户给出一个 `.txt` 文件路径，要求按章拆解。
- 用户要求从整本小说里提炼结构骨架、设定、伏笔、人物与文风。

不适用于：单章分析、非小说文本、需要联网抓取的文本。

## 模式

| 模式 | 默认 | 产物 | 契约 |
|---|---|---|---|
| 结构化拆解 | 是 | `<书名>_拆解/` 固定目录：四层剧情骨架、伏笔台账、开篇三章、世界观与金手指、六专题槽位、设定五集合、主角解构、文风、作者的话 | 段名与字段见 `assets/` 同名模板（唯一依据）；校验规则见 `scripts/contract.mjs`；判据与拆书方法论见 `references/`（先查 `references/索引.md`，按节的行范围读）；流程见 `workflows/05-10` |
| 快速报告 | 否 | 单份拆书报告 | `assets/报告模板.md` |

## 上下文纪律（直接决定成本）

三件事按顺序做，做反了成本会翻几倍：

1. **每阶段只加载一次**：进入一个阶段时读它需要的 `references/` 与 `assets/`，在同一阶段内不重读。阶段 5 要按组推进，但组与组之间共用同一份判据——重读一遍判据等于白花一遍 token。
2. **按节读，不整读**：`references/索引.md` 列出每份文件每个小节的起止行与体量（含 `判据/`、`解读/` 子目录）。用 `read` 的 `offset`/`limit` 只取需要的那几节。建主角卡不必读 `references/判据/人物提炼判据.md` 里的「反派：三层与强度」那一节，更不必读 `references/解读/人物提炼解读.md`。
3. **稳定的放前面、变化多的放后面**：把模板与判据放在上下文的靠前位置，批次数据（逐章原文、条目 JSON）放在靠后位置。宿主若支持 prompt 缓存，前缀稳定才能命中。

反例（都真实发生过）：为找一句出处通读整章、为改一行读整张逐章记录表、按七组把同一份判据读七遍。

### 视野分级

每个阶段能看见多远，是**定的**，不是凭感觉。越往后，看得越远、读得越薄：

| 档位 | 看得见什么 | 典型阶段 | 装得下的依据 |
|---|---|---|---|
| **全景** | 原文全文 | 05 切章 | 只有切章必须通读，且 prepare 只读一遍、不把原文装进上下文 |
| **全景（有界）** | 原文的一个明确子集 | 06 只读前三个叙事单元 | 开篇要给原文引句，再往后就转半景 |
| **半景** | 结构化记录（逐章记录、卷纲、幕纲）＋按需回捞的原句 | 07 逐章、08 设定库 | 幕 20-40 章约 31-62k token，装得下；一卷约 45 万 token 装不下 |
| **远景** | 上层产物（卷纲、分卷总表、台账） | 09 全书层、10 校验 | 全书层要回答的是「跨卷的形状」，单章原文看不出卷与卷之间的节奏 |

两条硬约束：

- **09 全书层禁止读原文**。它要做的三件事（分卷总表、全书大纲定稿、台账终核）都是从卷纲与台账归并出来的；读原文既装不下，也不解决它要回答的问题。
- **禁止按卷读原文**。07 里逐章记录按批读（10-20 章）、幕纲按幕读（20-40 章），这两档都装得下；按卷读是 45 万 token 量级，装不下。摘要不能替代原文来写幕纲——幕内因果链与情绪曲线在压缩时已经丢失。

### 判据与解读分离

`references/` 按**能不能拿来判定**分三层：

| 层 | 在哪 | 能不能拿来判定 |
|---|---|---|
| **判据** | `references/判据/` 下的文件（如 `references/判据/人物提炼判据.md`、`references/判据/幕边界判据.md`），以及各策略文件的 `J-` 判据表与「判断标准」段 | 能。每条都有强度（阈值/硬性/样本比例）与判定方法，读产物文本就能答 |
| **解读** | `references/解读/`（机制、实现路径、示例、来源）与 `references/解读提示.md`（作者自省题） | **不能**。前者解释「为什么这样有效」，后者要求知道作者想写什么（「反派和主角是镜像关系吗？」）——原文只能证明写了什么 |
| **策略正文** | 其余策略文件（设定、文风、伏笔、幕与节奏、结构、拆解总策略） | 部分能。它们同时含判据段（`J-`／`S-` 表、判断标准）与解读段（机制、路径），按节取判据那几节 |

拿解读题当判据会犯两种错：在不可判定的事上编出结论；或者反过来，逼着自己把有缺陷的书判成合格。**判定只看判据层的 `J-` 判据表与「判断标准」段里可执行的那部分**；解读层只在两种场合出现——向用户解释「这本书还有哪些作者视角的改进空间」，或对照自己写书。

拆分的直接收益：`references/判据/人物提炼判据.md` 约 6.3k tokens 可整读，机制与路径在 `references/解读/人物提炼解读.md`（约 15.6k tokens）——建人物卡时不必再为「为什么有效」付 token。

## 总流程

结构化拆解（默认），按序号依次进入，每个流程文件进入时读取、完成后进入下一组：

| 序号 | 步骤组 | 流程文件 |
|---|---|---|
| 05 | 结构化初始化 | `workflows/05-结构化初始化.md` |
| 06 | 口径锚定 | `workflows/06-口径锚定.md` |
| 07 | 卷循环 | `workflows/07-卷循环.md` |
| 08 | 设定库 | `workflows/08-设定库.md` |
| 09 | 全书层 | `workflows/09-全书层.md` |
| 10 | 校验交付 | `workflows/10-校验交付.md` |

快速报告，按序号依次进入：

| 序号 | 步骤组 | 流程文件 |
|---|---|---|
| 01 | 切章 | `workflows/01-切章.md` |
| 02 | 摘要 | `workflows/02-摘要.md` |
| 03 | 要素 | `workflows/03-要素.md` |
| 04 | 对账 | `workflows/04-对账.md` |

中断重入：用户说「继续拆」从 05 对账续跑（prepare 自动跳过已完成批）；「重拆」在 05 加 `--force --i-know` 归档重建（单用 `--force` 会报错列出会丢多少，先给人看）。流程之间不直接跳转，切换由本入口调度。

## 阶段自检

**05–09 每个阶段收口前，跑一次进度模式校验**：

```
node scripts/validate-output.mjs <产物目录> --mode progress
```

判读规则：

- **错误（error）必须为 0 才能进下一阶段。** 进度模式把「还没填」降成警告，所以剩下的 error 都是「填了但不合契约」——那是当场能改的，拖到 10 只会更贵。
- **只查「已写完的文件」**：整份文件还含「（待填）」时，出处与引句检查会整份跳过（不算它缺，也不拿它凑覆盖率）。所以这一检是随进度长出覆盖面的，不是一开始就全量。
- **警告可带过，但要写进阶段报告。** 警告里混着「正常未完成」与「可疑质量」，人要知道哪些留到了末尾。
- **只读这个阶段的产出**，别顺手修别的阶段的文件——修了会让 manifest 的状态与内容对不上。

为什么要有这一步（实测依据）：首次完整跑（《长安的荔枝》，7 个单元）时，三块内容并行填、最后才统一校验，24 条错误全堆到末尾——4 个集合为空、19 条结论缺出处、1 份产物整份没填。**没有一条是设计问题，全是「当场能发现、但没人看」**。分阶段跑的意义不是查得更严，是把修复点挪回它产生的现场。

> 一个先有鸡还是先有蛋的坑（首轮实际踩到）：**出处检查原先只在 deliver 模式跑**，而阶段自检用的是 progress——于是那一检对 19 条缺出处完全无感，门是开着的。现在两种模式都跑（块内按上面的「整份跳过」规则自然只会检查写完的文件），阶段自检才真的能挡住这批。

`10-校验交付` 跑的是同一个脚本的 **deliver 模式**（错误即不通过），与这里的 progress 模式是两个用法，不是两套规则。区别只在「未完成」怎么算：deliver 把缺失当错误，progress 当警告。

## 输入

| 字段 | 类型 | 必需 | 缺失时 |
|---|---|---|---|
| 小说文件路径 | 路径 | 是 | 停止并询问用户 |
| 书名 | 文本 | 否 | 取文件名去掉扩展名 |
| 拆解范围 | 文本 | 否 | 默认全书 |
| 模式 | 文本 | 否 | 默认结构化拆解 |
| 运行控制 | 文本 | 否 | 默认开始；支持「继续拆」（断点续跑，读 manifest 对账后跳过已完成批）、「重拆」（旧产物归档后重建）、「暂停」「取消」（产物保留） |

## 停止条件

- 文件不存在或不是 `.txt`：停止并说明。
- 切章后为 0 章：停止，报告「未识别到章节标题」，不猜。
- 章节数 < 3：停止并报告（护栏）。
