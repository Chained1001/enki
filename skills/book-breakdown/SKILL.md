# book-breakdown

## 何时使用

**只由用户显式调用，不做模糊意图识别。** 下列情形视为显式调用：用户点名 `book-breakdown`（或「拆书技能」「用拆书技能拆」），或明确要求按本技能的一套流程拆整本小说。

以下情形**不自动触发**，即使输入看起来像：

- 用户只给了 txt 路径并说「看看这本书」，没有点名本技能——先问是否要拆解，得到确认再进入。
- 用户问「这本书好不好看」「文笔怎么样」——这是评价需求，不是拆解需求。
- 用户只要单章分析、要写续写、要联网抓取——均不适用。

显式调用后仍需满足：

- 用户给出一个 `.txt` 文件路径，要求按章拆解。
- 用户要求从整本小说里提炼结构骨架、设定、伏笔、人物与文风。

不适用于：单章分析、非小说文本、需要联网抓取的文本。

## 模式

| 模式 | 默认 | 产物 | 契约 |
|---|---|---|---|
| 结构化拆解 | 是 | `<书名>_拆解/` 固定目录：四层剧情骨架、伏笔台账、开篇三章、世界观与金手指、六专题槽位、设定五集合、主角解构、文风、作者的话 | 段名与字段见 `assets/` 同名模板（唯一依据）；校验规则见 `scripts/contract.mjs`；判据与拆书方法论见 `references/`（先查 `references/索引.md`，按节的行范围读）；流程见 `workflows/05-10` |
| 快速报告 | 否 | 单份拆书报告 | `assets/报告模板.md` |

## 上下文纪律（直接决定成本）

三件事按顺序做，做反了成本会翻几倍：

1. **每阶段只加载一次**：进入一个阶段时读它需要的 `references/` 与 `assets/`，在同一阶段内不重读。阶段 5 要按组推进，但组与组之间共用同一份判据——重读一遍判据等于白花一遍 token。
2. **按节读，不整读**：`references/索引.md` 列出每份文件每个小节的起止行与体量。用 `read` 的 `offset`/`limit` 只取需要的那几节。建主角卡不需要读「反派：三层与强度」。
3. **稳定的放前面、变化多的放后面**：把模板与判据放在上下文的靠前位置，批次数据（逐章原文、条目 JSON）放在靠后位置。宿主若支持 prompt 缓存，前缀稳定才能命中。

反例（都真实发生过）：为找一句出处通读整章、为改一行读整张逐章记录表、按七组把同一份判据读七遍。

### 判据与解读分离

`references/` 里有两类内容，用法完全不同：

| 类型 | 在哪 | 能不能拿来判定 |
|---|---|---|
| **判据** | 各策略文件的 `J-` 判据表与「判断标准」段 | 能。每条都有强度（阈值/硬性/样本比例）与判定方法，读产物文本就能答 |
| **解读** | `references/解读提示.md` | **不能**。那是作者写书时拿来自省的题（「反派和主角是镜像关系吗？」），回答它需要知道作者想写什么，原文只能证明写了什么 |

拿解读题当判据会犯两种错：在不可判定的事上编出结论；或者反过来，逼着自己把有缺陷的书判成合格。**判定只看 J- 判据表与「判断标准」段里可执行的那部分**；解读提示只在两种场合出现——向用户解释「这本书还有哪些作者视角的改进空间」，或对照自己写书。

## 总流程

结构化拆解（默认），按序号依次进入，每个流程文件进入时读取、完成后进入下一组：

| 序号 | 步骤组 | 流程文件 |
|---|---|---|
| 05 | 结构化初始化 | `workflows/05-结构化初始化.md` |
| 06 | 口径锚定 | `workflows/06-口径锚定.md` |
| 07 | 卷循环 | `workflows/07-卷循环.md` |
| 08 | 设定库 | `workflows/08-设定库.md` |
| 09 | 全书层 | `workflows/09-全书层.md` |
| 10 | 校验交付 | `workflows/10-校验交付.md` |

快速报告，按序号依次进入：

| 序号 | 步骤组 | 流程文件 |
|---|---|---|
| 01 | 切章 | `workflows/01-切章.md` |
| 02 | 摘要 | `workflows/02-摘要.md` |
| 03 | 要素 | `workflows/03-要素.md` |
| 04 | 对账 | `workflows/04-对账.md` |

中断重入：用户说「继续拆」从 05 对账续跑（prepare 自动跳过已完成批）；「重拆」在 05 加 `--force --i-know` 归档重建（单用 `--force` 会报错列出会丢多少，先给人看）。流程之间不直接跳转，切换由本入口调度。

## 输入

| 字段 | 类型 | 必需 | 缺失时 |
|---|---|---|---|
| 小说文件路径 | 路径 | 是 | 停止并询问用户 |
| 书名 | 文本 | 否 | 取文件名去掉扩展名 |
| 拆解范围 | 文本 | 否 | 默认全书 |
| 模式 | 文本 | 否 | 默认结构化拆解 |
| 运行控制 | 文本 | 否 | 默认开始；支持「继续拆」（断点续跑，读 manifest 对账后跳过已完成批）、「重拆」（旧产物归档后重建）、「暂停」「取消」（产物保留） |

## 停止条件

- 文件不存在或不是 `.txt`：停止并说明。
- 切章后为 0 章：停止，报告「未识别到章节标题」，不猜。
- 章节数 < 3：停止并报告（护栏）。

|---|---|---|---|---|

| 快速 | 拆书报告 | Markdown | 见 `assets/报告模板.md` | 由用户指定；未指定时只输出到对话 |
