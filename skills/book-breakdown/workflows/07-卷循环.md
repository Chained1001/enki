# 07 卷循环

## 目的

完成PRD 产品流程节的阶段 4：按卷分批完成逐章记录、幕判定、幕纲、卷纲与伏笔台账。这是全流程花费最大的阶段，必须按批推进、批完成即落盘。

## 输入

| 字段 | 必需 | 说明 |
|---|---|---|
| 产物目录 | 是 | 06 已完成，装置口径已锚定 |
| manifest 卷表与批表 | 是 | 卷的起止章、批的章号区间。所有产物路径一律从 manifest 复制，不手打（全中文长路径易错） |

## 步骤

1. 取第一个存在未完成批的卷。出版书（`book_type=出版`）跳过幕判定：每个原文单元即一幕，直接进步骤 5 填幕纲。
2. 逐批处理（每批 ≤20 章）：
   a. 从 manifest 的 chapters 找到该批各章对应的 `原文/章节/` 文件并读取；manifest 里标了 `outlier: true` 的超长章（混入完本感言/附录），先定位叙事正文段再读，不整章通读。
   b. 为每章产出十二列取值：视角人物（多视角章写「多视角（甲／乙）」）、地点、出场人物（按已知别称用主名，新别名随手追加进别名词典）、一句话事件、剧情线（线名如 主线／支线·张荣水师，多线「、」分隔，无法判定写「主线」）、伏笔埋收（记「埋/收＋一句描述」，编号留步骤 6 统一定）、情绪（扬/抑/震荡）、章末钩型（危机/悬念/期待/反差/钝收）、爽点标记（无/小/中/大）。章字数由 prepare 写入，本步不填。
   c. **用脚本写行，不要读整表**：把本批各章取值写成 JSON 数组，跑
      `node ../scripts/write-rows.mjs <产物目录> --rows <本批.json>`。
      理由：逐章记录一册上千行，读整表再改会让每批都重读全书摘要，实测占总输入的七成。脚本只改目标章的行，标题与章字数（脚本列）自动保留；同批重跑不变更（幂等）。
      条目格式（9 个字段，全部必填；只补部分列加 `--partial`）：
      `[{"章号":1,"视角人物":"甲","地点":"车站","出场人物":"甲、乙","一句话事件":"…","剧情线":"主线","伏笔埋收":"埋：…","情绪":"扬","章末钩型":"悬念","爽点标记":"小"}]`
      脚本会拒绝：未知章号、缺字段、仍是「（待填）」、枚举非法、值含竖线或换行。先加 `--dry-run` 可只看不改。
      **条目 JSON 必须放在产物目录之外**（如系统临时目录）：放进产物目录会被 `validate-output` 判 `E_TREE_EXTRA`「不属于产物契约的文件」。
   d. 标记该批：`node ../scripts/progress.mjs <产物目录> --batch-done 卷号:批号`。
      同时上报本批用量（M-06）：`node ../scripts/cost.mjs <产物目录> --record --stage 4 --in <输入tokens> --out <输出tokens>`。
      逐批累加即可（50 批就是 50 次 `--record`）；取宿主返回的 usage，拿不到就跳过，不要填估算值。
3. 全卷批次完成后做幕判定，依 `../references/幕边界判据.md`：事件弧双锚定界（J-01）、五拍核对（J-02）、主角缺席段作高潮信号（J-05）；认知翻转点不强判，标「人工回填」。弧型归类与节奏判定按 `../references/幕与节奏策略.md`（循环模板认弧 S-02、爽点循环 S-03、情绪三值 S-05）。得出每幕起止章与幕型，幕数通常 2-6。
4. 若某幕结论依赖的章摘要质量不足，只允许回读该章原文补摘要，不重做整批。
5. 依 `../assets/幕纲模板.md` 新建幕纲文件（命名「卷NN-幕NN-弧名」）并填写十段；依卷纲骨架与 `../assets/卷纲模板.md` 填写卷纲九段，事件弧清单的行数必须等于该卷幕数。
6. 伏笔台账：汇总本卷逐章记录的埋收现象与复盘章，识别与对账按 `../references/伏笔识别策略.md`（信号清单 S-01、复盘反填 S-03、埋收对账 S-04），按全局连续编号写入「故事剧情/伏笔台账」（编号/描述/类型/埋点章/强化章/回收/引爆章/回收幕/跨度/涉及实体/重要度/状态）。
7. 回核「全书大纲·核心冲突装置」段：本卷证据证伪初版处回填修订并注明（口径锚是活文档）。
8. 该卷全部产物落盘后进入下一卷；全部卷完成后标记阶段 4 done。

## 产出

- 逐章记录全卷成稿（行数不变，十二列补全，含章字数与剧情线）。
- 幕纲每幕一份、卷纲每卷一份、伏笔台账新增行。

多卷并行时：逐章记录与伏笔台账可先写分卷片段（「工作/逐章记录-卷N」「工作/伏笔台账-卷N」，新增别名写「工作/别名-卷N」），收口阶段合并重编号，避免同文件写冲突。

## 停止条件

- 批失败（产出不合格或读取超限）：同批重试一次；仍失败即停该卷，向用户报告失败的章区间与原因，不静默跳过。用户可指示跳过该卷继续其他卷（卷间独立）。
- 幕数超出 2-6：不停止，继续填写并在幕定位段注明例外。
- 续跑时源哈希不匹配：prepare 已拒绝并说明，本流程停止等待用户裁决（重拆或恢复源文件）。
