# 07 卷循环

## 目的

完成PRD 产品流程节的阶段 4：按卷分批完成逐章记录、幕判定、幕纲、卷纲与伏笔台账。这是全流程花费最大的阶段，必须按批推进、批完成即落盘。

## 输入

| 字段 | 必需 | 说明 |
|---|---|---|
| 产物目录 | 是 | 06 已完成，装置口径已锚定 |
| manifest 卷表与批表 | 是 | 卷的起止章、批的章号区间。所有产物路径一律从 manifest 复制，不手打（全中文长路径易错） |

## 视野

**半景（逐章）＋全景（按幕）**｜读原文：逐章记录阶段**按批读**原文（一批 10-20 章）；幕判定后**按幕重读**原文；禁止按卷读

**幕 20-40 章约 31-62k token，装得下**；**按卷读是 45 万 token 量级，装不下**。这是全流程唯一一处必须回读原文的结构判断——摘要里已经丢了幕内因果，不能拿来写幕纲。

三档含义见 `../SKILL.md` 的「视野分级」节；与上下阶段的衔接见 PRD 产品流程节的「视野分级」横向规则。


## 步骤

1. 取第一个存在未完成批的卷。**两类书都做幕判定，不跳过**：
   - 网文：幕＝卷内事件弧，按步骤 3 的双锚定界判定，幕数通常 2-6。
   - 出版书（`book_type=出版`）：幕＝原文单元（「第N幕」或「第N章」），单元边界在切章时就已确定，不需要再判「哪里是幕」；但**幕纲仍要写**，且要按幕内小节拆出五拍（一章 3.7 万字里当然有五拍，只是拍不落在章号上，落在章内相对位置）。不要因为「幕已经定了」就把幕纲省成章纲——省了，「能看出事件弧怎么走」这一层就没了。
2. 逐批处理（每批 ≤20 章）：
   a. 从 manifest 的 chapters 找到该批各章对应的 `原文/章节/` 文件并读取；manifest 里标了 `outlier: true` 的超长章（混入完本感言/附录），先定位叙事正文段再读，不整章通读。
   b. 为每章产出十三列取值：视角人物（多视角章写「多视角（甲／乙）」）、地点、出场人物（按已知别称用主名，新别名随手追加进别名词典）、一句话事件、剧情线（线名如 主线／支线·张荣水师，多线「、」分隔，无法判定写「主线」）、伏笔埋收（记「埋/收＋一句描述」，编号留步骤 6 统一定）、情绪（扬/抑/震荡）、章末钩型（危机/悬念/期待/反差/钝收）、爽点标记（无/小/中/大）。章字数由 prepare 写入，本步不填。
   c. **用脚本写行，不要读整表**：把本批各章取值写成 JSON 数组，跑
      `node ../scripts/write-rows.mjs <产物目录> --rows <本批.json>`。
      理由：逐章记录一册上千行，读整表再改会让每批都重读全书摘要，实测占总输入的七成。脚本只改目标章的行，标题与章字数（脚本列）自动保留；同批重跑不变更（幂等）。
      条目格式（9 个字段，全部必填；只补部分列加 `--partial`）：
      `[{"章号":1,"视角人物":"甲","地点":"车站","出场人物":"甲、乙","一句话事件":"…","剧情线":"主线","伏笔埋收":"埋：…","情绪":"扬","章末钩型":"悬念","爽点标记":"小"}]`
      脚本会拒绝：未知章号、缺字段、仍是「（待填）」、枚举非法、值含竖线或换行。先加 `--dry-run` 可只看不改。
      **条目 JSON 必须放在产物目录之外**（如系统临时目录）：放进产物目录会被 `validate-output` 判 `E_TREE_EXTRA`「不属于产物契约的文件」。
   d. 标记该批：`node ../scripts/progress.mjs <产物目录> --batch-done 卷号:批号`。
      同时上报本批用量（M-06）：`node ../scripts/cost.mjs <产物目录> --record --stage 4 --in <输入tokens> --out <输出tokens>`。
      逐批累加即可（50 批就是 50 次 `--record`）；取宿主返回的 usage，拿不到就跳过，不要填估算值。
3. **幕判定是流式的，不等全卷批次做完**：每批（≤20 章）读原文时同批记下四个「弧候选信号」——开启锚候选、结算锚候选、主角缺席段、章长突变——写进「工作/增量/幕NN.json」。累积到 20–40 章、或信号闭合成一条弧时，**立刻定这一幕并写幕纲**，不等整卷。

   为什么不能等全卷：`../references/判据/幕边界判据.md` 自己记了实测——大奉卷 1 有 230 章、均章 3,131 字，按 J-03 算出的幕体量是 38–115 章（12–36 万字）。12–36 万字按 1.6 字/token 是 75–225k token，**一幕就吃满上下文**；「全卷批次完成后」还意味着要先攒完 45 万 token 的 231 行记录才能开始判。等全卷，等于永远判不了。

   判幕要重读原文，不靠十二列摘要：开启锚与结算锚是不是同一弧、五拍齐不齐、人物弧转折点在哪，十二列里都没有。十二列只用来定位候选区间，不作为判定依据（判据见 `../references/判据/幕边界判据.md`：事件弧双锚定界 J-01、五拍核对 J-02、主角缺席段作高潮信号 J-05；认知翻转点不强判，标「人工回填」）。

   弧型归类与节奏判定按 `../references/幕与节奏策略.md`（循环模板认弧 S-02、爽点循环 S-03、情绪三值 S-05）。**出版书**：幕＝原文单元，本步跳过「哪里是幕」，只判每幕的幕型与五拍落点（用「幕的粒度档位」的小幕口径，按章内相对位置）。4. 幕边界敲定后**必须重读本幕原文**再写幕纲，不靠逐章摘要拼。摘要是压缩产物，幕级的因果链与情绪曲线在压缩中已经丢失——用摘要写幕纲，产出的是章节的重新排列，不是一幕的结构。按幕读：一幕 20-40 章约 31-62k token，装得下；不要按卷读（45 万 token 装不下）。只回读「摘要质量不足的那一章」是不够的，那样看不到幕内的呼应。
5. 依 `../assets/幕纲模板.md` 新建幕纲文件（命名「卷NN-幕NN-弧名」）并填写十段；依卷纲骨架与 `../assets/卷纲模板.md` 填写卷纲九段。**事件弧清单的行数不在填写时对，卷末一次性校验**：流式判幕时每定一幕就补一行弧，卷末再用脚本核「弧数＝幕数」。边写边对会逼你为了凑够行数先编弧名，而弧是判出来的、不是凑出来的。

   **写完就把这两个文件标成 filled**，一个文件一次调用：

   ```
   node ../scripts/progress.mjs <产物目录> --file 故事底本/故事剧情/幕纲/卷01-幕01-弧名.md:filled --file 故事底本/故事剧情/卷纲/卷01-第一卷.md:filled
   ```

   为什么要标：骨架建成时每个文件都记 `skeleton`，此后没有任何地方会改它。中断在这一卷中途，重跑时看 manifest 只能知道「这一批的逐章记录做完了」，**看不出那几份幕纲文件到底是空的还是写好了**。而 `prepare` 对已存在文件是 `continue`（不覆盖），所以重跑也不会把它补好——不标状态，只能把十段重新读一遍才能判断，一册几十个幕纲就是几十次无谓读取。

   注意 `--file` 一次可给多个，但路径必须真实存在：给不存在的文件记状态会报 `E_FILE`，这是刻意的——允许记不存在的文件，等于又造一套「说与做不一致」的账。**出版书的卷纲**：骨架已由 prepare 预置（每卷一份），事件弧清单一列填该卷的原文单元（一行一个单元），行数＝该卷幕数；不拆事件弧，弧型列填「原文单元」。
6. 伏笔台账（**幕末增量记账，编号由脚本排**）：
   a. 先把本卷的埋收现象写成增量行，落到「工作/伏笔台账-卷N」（表头与主台账一致）。识别与对账按 `../references/伏笔识别策略.md`（信号清单 S-01、复盘反填 S-03、埋收对账 S-04）。
      **编号列留空**——你只报「看到了什么」（描述/类型/埋点章/涉及实体/重要度/状态），不报编号。手排号必然撞车或跳号，实测就是编号对不上、引用大面积悬空。
   b. 幕末跑 `node ../scripts/merge-foreshadow.mjs <产物目录>`：脚本把增量合并进主台账、连续重编号，并同步改写卷纲/幕纲/逐章记录里的全部 `F\d{3}` 引用。
   c. 脚本报「悬空引用」时：那是台账里根本不存在的编号，回到对应产物把它改成真实编号，或补一条台账行。不要放着不管——校验器的 `E_FORESHADOW_REF` 会拦交付。
   d. 合并要幂等：同一批增量重跑不会产生重复条目（按描述+埋点章+类型判重），所以重跑是安全的。
   e. 合并完增量文件可以留着（契约接受「工作/伏笔台账-卷N」），也可以删；删了下次合并不影响主台账。
7. 回核「核心冲突装置」，**回填写增量、不写全书大纲**：

   ```
   node ../scripts/progress.mjs <产物目录> --file-state 故事底本/故事剧情/全书大纲.md
   ```

   它直接打印这个文件在 manifest 里的状态（`skeleton` 或 `filled`）：

   两个分支都只写「工作/增量/装置-回填-卷N.md」，**不改全书大纲**：

   - `skeleton`：06 那一步没跑完就中断了，装置初版还是骨架。本卷证据够就现在补一份初版进增量。
   - `filled`：初版已成稿。本卷证据证伪初版处，写一份回填修订进增量并注明是哪一条被证伪。

   全书大纲的唯一一段由 09 定稿时一次性写入。07 直接改它，就会出现同一段文本被三个阶段各改一遍、产物里两版并存——实测痕迹是同一个文件里既有「## 核心冲突装置」又有「### 装置段终稿」。

   为什么非查不可：这两种情况长得一样——都有一份「全书大纲」，都有个装置段。区别是前者的内容是占位符、可以直接覆盖，后者是 06 逐字读开篇三章写出来的结论、覆盖掉就没了。不查状态，回填这一步只能靠猜。
8. 该卷全部产物落盘后进入下一卷；全部卷完成后标记阶段 4 done。

## 产出

- 逐章记录全卷成稿（行数不变，十三列补全，含章字数、剧情线与爽点强度/类型）。
- 幕纲每幕一份、卷纲每卷一份、伏笔台账新增行。
- 卷级派生统计（脚本给，不要手算）：逐章记录成稿后跑

  ```
  node skills/book-breakdown/scripts/volume-stats.mjs <产物目录>
  ```

  它从逐章记录算三样东西，把结果抄进卷纲「节奏与章末钩画像」段，**不要自己数**：
  每卷爽点章数与爽点密度、中爽点间隔中位数、钩型分布与最大连续同型钩。

  为什么必须走脚本：这三样都是「现成的列 + 一次分组统计」，手算没有正确答案可对照——
  数错了没人知道，产物里也看不出是数是猜。加 `--json` 可拿结构化结果。

  脚本报出的「不在枚举内、未计入统计的取值」要照它点名去改正：那些值（如手写的「危机钩」）
  不计入统计，留着会让各项数值偏低而不自知。

多卷并行时：逐章记录与伏笔台账可先写分卷片段，**一律放在「工作/增量/」下**（「工作/增量/逐章记录-卷N」「工作/增量/伏笔台账-卷N」，新增别名写「工作/增量/别名-卷N」），避免同文件写冲突；收口阶段用 `merge-foreshadow.mjs` 合并重编号（脚本按指纹去重，两卷各记一次的同一件事只留一条）。

为什么统一到「工作/增量/」：分卷片段原先散落在「工作/」顶层，那一层只有三个常驻文件（manifest、逐章记录、别名词典），多出来的片段既不在契约里、也不在增量目录里，校验器只能判它「不属于产物契约的文件」（E_TREE_EXTRA）。增量目录是过程目录，契约对它按命名规则放行，片段本来就该在那儿。

## 停止条件

- 批失败（产出不合格或读取超限）：同批重试一次；仍失败即停该卷，向用户报告失败的章区间与原因，不静默跳过。用户可指示跳过该卷继续其他卷（卷间独立）。
- 幕数超出 2-6：不停止，继续填写并在幕定位段注明例外。
- 续跑时源哈希不匹配：prepare 已拒绝并说明，本流程停止等待用户裁决（重拆或恢复源文件）。
