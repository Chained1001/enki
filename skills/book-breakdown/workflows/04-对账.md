# 04 对账

所属技能：book-breakdown。入口见 `../SKILL.md`。

## 目的

检查章节、摘要、要素三者是否对得上，给出可核对的数字。

## 输入

| 字段 | 来源 | 必需 | 缺失时 |
|---|---|---|---|
| 章节列表与字数 | 01 切章 | 是 | 停止，交回入口 |
| 摘要表 | 02 摘要 | 是 | 停止，交回入口 |
| 要素表 | 03 要素 | 是 | 停止，交回入口 |
| 报告文件 | 用户指定的输出路径 | 是 | 见下方「报告没落盘时」 |

## 步骤

1. **跑脚本对账，不要手算**：

   ```
   node skills/book-breakdown/scripts/reconcile.mjs <报告文件> --source <小说 txt>
   ```

   它读报告文件，跑 `detectChapters`（与 01 同一口径）算章节数，然后打印一张对账表：

   | 项 | 期望 | 实际 | 结论 |
   |---|---|---|---|
   | 摘要行数 | 章节数 | 报告里的摘要行数 | 对得上／对不上 |
   | 摘要超 60 字行数 | 0 | 实际行数 | 对得上／对不上 |
   | 无法摘要行数 | — | 实际行数 | 只计数，不判失败 |
   | 要素首现章越界 | 0 | 越界条数 | 对得上／对不上 |
   | 各章字数和＝总字数 | 报告自报的总字数 | 脚本算出的和 | 对得上／对不上 |

2. **把这张表贴进报告的「对账」节**，原样转述，不自行改数、不自行补结论。

3. **退出码决定下一步**（这是这一步唯一可机器判定的东西）：

   - `0`：全对。
   - `1`：有项对不上。把对不上的那几行原样报给用户，**不自动修补**（修补无证据来源，见下方停止条件）。
   - `2`：参数错（缺 `--source`、报告路径写错）。照错误信息改，不是对账失败。

### 报告没落盘时

快速模式未指定输出路径时，报告只在对话里、没有文件。此时脚本报 `E_FILE`——**不要退回手算**。

正确做法：让用户确认输出路径，把报告写下来再跑；或者明确告诉用户「本次无文件可核，报告未经对账」。手算的对账表和没做过对账在产物上长得一样，区别只在有人复核时才会暴露。

## 为什么必须走脚本

这五项都是确定性算术：摘要行数数一遍、首现章比一次区间、字数和加一遍。手算的问题不是慢，是**没有正确答案可对照**——算错了没人知道，产物里也看不出是数是猜。

退出码是关键。此前 `04:30` 只说「任一核对不通过：在报告中标注，交回入口说明」，没有任何机器可查的判据。于是「标注了」和「没标注」在产物上无从分辨。

## 产出

对账表：项、期望、实际、结论（由脚本打印，原样贴入报告）。

## 停止条件

- 任一核对不通过：在报告中标注并对用户说明，不自动修补。修补需要证据来源，而对账只能指出「不一致」，指不出「哪个是对的」。
