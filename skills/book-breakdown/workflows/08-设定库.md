# 08 设定库

## 目的

完成PRD 产品流程节的阶段 5：设定全库——人物（主角解构、配角卡、索引对账）、五集合、世界观、金手指、六专题、文风。

## 输入

| 字段 | 必需 | 说明 |
|---|---|---|
| 产物目录 | 是 | 07 已完成，逐章记录与卷级产物成稿 |

## 步骤

（总纪律见 `../references/拆解总策略.md`；设定提炼见 `../references/设定提炼策略.md`，人物提炼见 `../references/人物提炼策略.md`，文风方法见 `../references/文风分析策略.md`；术语查 `../references/拆书概念辞典.md`。）

1. 定稿「工作/别名词典」：去重合并卷循环各批累积的别名行，按 `../assets/别名词典模板.md` 的归并规则复核；剧透约束——揭示章之前不归并同体双名，标注「揭示后归并」。同字异人与词形歧义按主次判定判据 J-07 核对，存疑行保留警示。
2. 人物主次：从逐章记录统计出场（全局＋分卷双口径）与视角章占比，依 `../references/主次判定判据.md` 判定；分母与扫描代位口径见 J-01（逐章记录未完成时用确定性单遍扫描代位，不用 bash 通配——输出顺序非确定）；主角边缘带 55%-60% 按 J-08 裁决；候选名单只是提示，一律以原文实际用词为准（扫描 0 次即弃）。关键事件参与作功能位修正；双主角书建两个主角文件夹。
3. **建实体索引，定取证范围（本步决定阶段 5 的成本）**：跑
   `node ../scripts/entity-index.mjs <产物目录> --list` 看全部实体与出现章数，`--entity 名称` 查单个的章号与建议取证章。

   建卡**不得**读该实体的全部出场章——主角可能出现在六成章节里，读不完。取证上限：

   | 实体档位 | 取证章数 | 取哪几章 |
   |---|---|---|
   | 主角、主要配角（J-03 弧内达标） | ≤6 章 | 首现章、身份/能力揭示章、弧光崩塌章、高光章、回收章、末次章 |
   | 次要角色 | ≤2 章 | 首现章、首次有行动的一章 |
   | 集合条目（势力/地点/物品/概念） | ≤3 章 | 首现章、规则或功能被说明的一章、状态变化章 |

   三档数字以 `contract.mjs` 的 `THRESHOLDS.取证章数_主角／次要角色／集合条目` 为准，
   脚本默认取主角档（6 章），换档用 `--sample 次要角色`／`--sample 集合条目`。

   **「首现章」只从脚本输出里抄，自己不数**（C-12）：要素表与人物卡的首现一律取
   `entity-index.mjs --json` 的 `首现章` 字段。实测出过错——appendix 里写「首次出场 239 章」，
   实为第 197 章：出场章不连续，人眼数「第几行」会随断档偏移。脚本按 `min(章号)` 算，不会错。
   同理，出场章数、末次章、建议取证章也都只转述脚本结果，不手算。

   **取引句用脚本，不要为了一句出处通读整章**：
   `node ../scripts/quote-finder.mjs <产物目录> --entity 名称`（不给 `--chapters` 时按上述采样规则自动选章）。
   脚本按 manifest 定位章节文件、按「工作/别名词典」展开别称（避免实体在原文写作别称时漏检），把命中的原句连章号一起打印；`--context` 带前后句，`--max N` 控制每章句数。
   它省的是最大一笔：410 张卡各读约 3 章 ≈ 1,230 章、约 370 万字，比阶段 4 读全书一遍还贵；脚本只吐出命中的那几句。
   脚本报「所有目标章均未命中」时，先补别名词典再重试，不要改去通读整章。

   证据仍不足时**用逐章记录的「一句话事件/伏笔埋收」列补上下文**，不扩读原文；再不足则按 F-14 不写入、记入存疑清单。卡片里写「未核」好过编造。
4. 主要配角的卡数＝J-03 弧内达标数（判据优先于任何配额）；主角：依 `../assets/主角解构模板.md` 在 `人物/主角/<人名>/` 建五文件（人物卡含六维人格）；前序卷未拆解时，成长轨迹等跨卷字段允许「推断：」占位，待对应卷完成后回填。
5. 次要角色按 `../assets/人物卡模板.md` 写基础卡；填写人物索引（一行一角色，主角一行计一文件夹，文件路径一律为产物根相对路径）与人物关系表（两端都在索引中）；统计口径写进索引头注；出版书（单卷）两列主次恒重复时允许合并填写并注明「单卷」。
6. 四个集合逐一条目建卡：势力、地点、物品、概念按 `../assets/` 下同名模板；每集合索引行数必须等于条目文件数。
7. 世界观（概览层，指向专题）、金手指（依 `../references/金手指判据.md` 判类型与边界，八类枚举可多选）。
8. 六个专题槽位逐个填：涉及判定必填（涉及/弱涉及/本题材不涉及＋依据＋指向）；不涉及的槽位只写三行判定，删除其余待填段。
9. 文风定性六段按 `../assets/文风模板.md` 填写；「定量指纹」段已由脚本生成，不改动数值。
10. 全部完成后标记阶段 5 done，并上报本阶段用量（M-06）：
    `node ../scripts/cost.mjs <产物目录> --record --stage 5 --in <输入tokens> --out <输出tokens>`。
    按组分别 `--record` 累加即可；取宿主返回的 usage，拿不到就跳过。

分批与并行：本阶段按「人物 / 势力 / 地点 / 物品 / 概念 / 世界观与专题 / 文风」七组推进，一组一次，不要在一次调用里铺开全部实体。多代理并行时按组或按集合分派，各自只写自己的产物文件——本阶段各文件互不重叠，不需要像阶段 4 那样写片段再合并。

**判据只加载一次，按节读**：先读 `../references/索引.md`，再按「常用取用组合」表用 `read` 的 `offset`/`limit` 取所需小节，不要整读。

| 组 | 需要读的节 |
|---|---|
| 人物·主角 | `../references/人物提炼策略.md` 的「主角三要素与三级欲望链」「读者凭什么跟百万字」「主角成长弧怎么排」「人物认知怎么控制」 |
| 人物·主要配角 | 同文件「配角与群像」「人物关系怎么织」 |
| 人物·反派 | 同文件「反派：三层与强度」 |
| 势力/地点/物品/概念 | `../references/设定提炼策略.md` 的「世界铁则与规则」（地理类另加「随文潜入与世界观暗面」） |
| 世界观与专题 | 同文件「力量体系与天花板」 |
| 文风 | `../references/文风分析策略.md` 全份 |

七组共用同一份判据：**组间不要重读**。整读 `../references/人物提炼策略.md`（约 20k tokens）一次抵得上读六七章原文，七组各整读一遍就是十几万 tokens——这是本阶段最容易被忽略的花费。

## 产出

设定库全部文件成稿：主角文件夹、人物卡、五集合条目卡与索引、世界观、金手指、六专题、文风。

## 停止条件

- 无硬停止：宁可写「无」或「本题材不涉及」，不编造设定。
- 出处给不出的条目按 F-14 不写入，改列入最终交付报告的「存疑清单」。
