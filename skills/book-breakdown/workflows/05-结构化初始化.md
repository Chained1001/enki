# 05 结构化初始化

## 目的

完成PRD 产品流程节的阶段 0-2：拿到原文路径，运行预处理与骨架落位，向用户报告初始化结果；支持续跑与重拆两种重入。

## 输入

| 字段 | 必需 | 说明 |
|---|---|---|
| 原文 txt 路径 | 是 | 用户在阶段 0 已给出；未给时先问，不猜路径 |
| 运行控制 | 否 | 「继续拆」走续跑；「重拆」走归档重建；缺省首次运行 |

## 步骤

1. 自查路径存在且为 txt（脚本还会再查，先自查避免空跑）。
2. 首次运行：执行 `node skills/book-breakdown/scripts/prepare.mjs <原文路径>`。
3. 续跑：同一命令，prepare 自动对账 manifest 并跳过已完成部分，向用户报告恢复点（阶段、卷、批）。
4. 重拆：加 `--force` **与** `--i-know`。单用 `--force` 会报错并列出「会丢多少个已填文件」与归档路径——那一步是给人看的，**必须把这条消息原样转述给用户并等他确认**，不要自己补上 `--i-know` 再跑。用户确认后，旧产物归档为 `_旧N` 目录（不删除），新目录从骨架重建。
5. 读 manifest，输出初始化报告：书名、类型（网文/出版）、章数、卷数与逐卷卷名、总字数、批数（规模预告：全书投入≈批数个批次）、骨架文件数。
6. 标记阶段 2 完成：`node skills/book-breakdown/scripts/progress.mjs <产物目录> --stage 2:done`。

## 产出

- `<书名>_拆解/` 目录骨架就绪（章节文件、manifest、全部固定产物骨架、卷纲骨架、定量指纹已生成）。
- 初始化报告一段。
- manifest 的文件状态与实际内容一致（若续跑后怀疑状态过期，跑 `progress.mjs <产物目录> --resync-files` 按内容重判）。

## 停止条件

- prepare 退出非 0：向用户原样转述 stderr 的中文原因后停止；不手工建目录、不猜测切章。
- 章节数少于 3：报告「疑似不支持的文本结构」，停止。
- 用户要查进度：`node skills/book-breakdown/scripts/progress.mjs <产物目录>` 只读输出，不打断流程。
