# 09 全书层

## 目的

完成PRD 产品流程节的阶段 6：全书层收口——分卷总表、全书大纲定稿、伏笔台账终核。

## 输入

| 字段 | 必需 | 说明 |
|---|---|---|
| 产物目录 | 是 | 08 已完成，设定库成稿 |

## 视野

**远景**｜读原文：**禁止**

全书层要看的是「跨卷的形状」——分卷总表、全书大纲、台账终核，这些只能从卷纲与台账归并。读原文既装不下（45 万 token），也不解决全书层要回答的问题：单章原文看不出卷与卷之间的节奏。

三档含义见 `../SKILL.md` 的「视野分级」节；与上下阶段的衔接见 PRD 产品流程节的「视野分级」横向规则。


## 步骤

1. **先跑脚本写「爽点密度」列，再人工填叙述列**：

   ```
   node scripts/volume-stats.mjs <产物目录> --write-total
   ```

   它从逐章记录算出每卷的爽点密度（卷内爽点章数 ÷ 本卷章数），写进总表对应行。**这一步不要手算**：密度是纯反转（数两列相除），手算与脚本算出两个值时没人知道该信哪 个，而它正是「这一卷节奏闷不闷」的唯一可复核指标。

   逐章记录还是骨架的卷，该格写「（待填）」而不是 0%——0% 表示「这一卷一个爽点都没有」，与「还没数」是两件事。

2. 逐卷填写分卷总表其余列（表头已由骨架固定，按契约 16 列列序）：卷、卷名、卷名来源与释义、起止章、章数、字数与均章长（从 manifest 取数）、**爽点密度（上一步脚本写，不要动）**、一句话钩子、核心压力源（允许非人格化）、本卷主要对手、主角状态变化、新地图与新势力、卷末状态（悬念定格方式）、追读钩、时间跨度、商业外证。可空列三处：本卷主要对手在情感流无外敌时留空（压力源写非人格化）、时间跨度无数据时留空、商业外证无数据写「无」；其余列必填。
2. 全书大纲定稿：骨架段清单（8-12 段不凑数，每段标段型与起止章）＋九节点检查单（每节点章号＋一句原文依据）；骨架定位的反向检查按 `../references/结构拆解策略.md`（三幕反推 S-01、激励事件 S-02、中点双形态 S-04、蓄势段识别 S-06）；**核心冲突装置在这一步一次性定稿**：读「工作/增量/阶段06-装置.md」与各卷的「工作/增量/阶段07-装置-卷N.md」，合并成唯一一段写进全书大纲的「核心冲突装置」段，保留「哪一条被哪一卷证伪、改成什么」的修订说明。

   为什么定稿只在这一处：06 写初版、07 逐卷回填、09 定稿，三个阶段各改一次同一段文本，而此前没有任何「只允许一处定稿」的规则。实测后果是同一个文件里两版并存（`## 核心冲突装置` 与 `### 装置段终稿（收口阶段统一定论）`），读者不知道该信哪个。现在 06、07 只写增量，全书大纲的这一段只有 09 会写，且写一次就定稿。
3. 伏笔台账终核：跨卷伏笔埋收对账（埋点、强化、回收的章号与卷纲幕纲一致），状态复核，未收伏笔确认是否「续作预留」。
4. 标记阶段 6 done，并上报本阶段用量（M-06）：`node scripts/cost.mjs <产物目录> --record --stage 6 --in <输入tokens> --out <输出tokens>`。

**阶段自检**：收口前按 `../SKILL.md` 的「阶段自检」跑一次 `node scripts/validate-output.mjs <产物目录> --mode progress`；错误为 0 才进下一阶段，警告记进阶段报告。

## 产出

- 分卷总表成稿（两类书都有此产物；出版书的卷层由 prepare 预置骨架，本步补内容）。
- 全书大纲四块齐备。
- 伏笔台账终稿。

## 停止条件

- 无硬停止：证据不足的节点在检查单中写「未定位」并说明，不硬凑章号。
