# 06 口径锚定

## 目的

完成PRD 产品流程节的阶段 3：先产出全书「核心冲突装置」初版作为后续所有卷的口径锚（D-11），并顺带完成开篇三章专项（本来就要读开篇，零额外成本）。

## 输入

| 字段 | 必需 | 说明 |
|---|---|---|
| 产物目录 | 是 | 05 已完成，骨架就绪 |

## 视野

**全景（有界）**｜读原文：允许，但**只读前三个叙事单元**全文

开篇三章是全文最该逐字读的地方（入场钩子、信息投放都要原文引句）；再往后就转入半景，否则装不下。

三档含义见 `../SKILL.md` 的「视野分级」节；与上下阶段的衔接见 PRD 产品流程节的「视野分级」横向规则。


## 步骤

1. 读 `原文/章节/` 的前三个叙事单元全文（网文为前三章；出版书为前三个原文单元）；「原文/作者的话」有结构自述段则读，九成是逐章致谢类时跳过（spike 实证：此类书作者自述无结构价值）。全流程总纪律见 `../references/拆解总策略.md`。
2. 装置初版**写进增量片段，不写全书大纲**：按 `../assets/全书大纲模板.md` 里「核心冲突装置」的字段写一份初版——装置名称、首次出现章、在卷界/中点/高潮处的结构职能——落到「工作/增量/装置-初版.md」。装置判定的反向检查见 `../references/结构拆解策略.md`。

   为什么初版不直接写进全书大纲：这一段会被 06 写一次、07 回填一次、09 定稿一次，**同一段文本被三个阶段各改一遍，且没有任何「只允许一处定稿」的规则**。实测留下的痕迹就是同一个文件里既有 `## 核心冲突装置` 又有 `### 装置段终稿（收口阶段统一定论）`——两版并存，读者不知道该信哪个。

   改法：06 与 07 只写「工作/增量/」，**只有 09 往「故事底本/故事剧情/全书大纲.md」的「核心冲突装置」段落定稿**（唯一一段）。07 的回填写「工作/增量/装置-回填-卷N.md」。
3. 按 `../assets/开篇三章模板.md` 完整填写开篇三章：每章四项（入场钩子原文引句＋手法、信息投放、人设立住手段、章末钩＋钩型），末段可复用套路至少 3 条；钩型分型见 `../references/幕与节奏策略.md` 的 S-04。
4. 每条结论带「第 N 章＋原文引句」出处；给不出出处的判断写「推断：」前缀，不编造。
5. 标记阶段 3 与装置段状态——**两件事都要做，标阶段不等于标文件**：

   ```
   node ../scripts/progress.mjs <产物目录> --stage 3:done --file 故事底本/故事剧情/全书大纲.md:filled
   ```

   为什么必须标文件状态：`prepare` 建骨架时把每个文件记成 `skeleton`，此后**没有任何地方会把它改成 `filled`**。于是中断后重跑，看 manifest 只能知道「阶段 3 做完了」，看不出「全书大纲的装置段到底填没填」——07 第 7 步要回填装置段，它必须先知道能不能直接改。这不标，回填就只能靠猜，猜错就覆盖掉已经填好的内容。

   同时上报本阶段用量（M-06）：`node ../scripts/cost.mjs <产物目录> --record --stage 3 --in <输入tokens> --out <输出tokens>`。
   用量取宿主返回的 usage，不要自行估算；拿不到就整段跳过，不要填假数（`--report` 会用产物算出的下界核对，填低了会告警）。

## 产出

- 全书大纲（仅核心冲突装置段成稿）。
- 开篇三章成稿。

## 停止条件

- 无硬停止：前三单元不足以判断装置时，输出「推断」并继续；装置在后续卷循环中如被证伪，回到本步修订初版并记录改动。
